# Prisma 8 architecture spec

The handoff from the [Prisma 8 Wayfinder map](https://github.com/OpenSaasAU/stack/issues/1029) to the build effort. Thirty-eight tickets closed between 2026-08-24 and 2026-09-03; their decisions are ADR-0038 through ADR-0065 in `docs/adr/`, with amendments to eighteen earlier records and a rewritten vocabulary in `CONTEXT.md`. This document does not restate those decisions. It names the target architecture in one place, points at the record that holds each decision, orders the build, inventories the consumers the build touches, and lists what must be re-verified when Prisma 8 ships a non-RC toolchain.

**Where this document and an ADR disagree, the ADR is right and this document is stale.** Each ADR carries its own Considered Options and Consequences; a reader who needs the _why_ goes there, not here.

## Scope and standing rules

The destination fixed at charting: an architecture spec naming what the ORM boundary becomes, what happens to `context.db`, the generator's output artifact, the migration workflow, and the access-control internals. The map does not do the migration. Everything below is decided; nothing below is built.

Standing rules the whole effort was decided under:

- The project has **no external users**. Breaking changes ship as minors with the break named in the changeset. No migration guides, codemods, deprecation windows, or major-version ceremony.
- **Prisma 7 is dropped entirely.** No dual support, no transition window.
- **SQLite is not a supported provider.** Postgres is the one provider; `db.provider` survives as a postgresql-only key so the seam exists if scope is ever redrawn.
- **Existing dev databases are recreated, not migrated** ([ADR-0048](../../docs/adr/0048-the-deleted-psl-constructs-become-config-defaults-not-ddl.md)). Every list's id changes shape, no example ships a database, no seed id is stable. Reseeding is the only path.
- **Versions.** Every decision was reasoned against the `@prisma/orm-*` family at `8.0.0-rc.8` and, from [#1070](https://github.com/OpenSaasAU/stack/issues/1070) on, run against the `prisma@8.0.0-rc.12` CLI, which wraps that same `rc.8` toolchain. `@prisma/client` has no 8.x release and is not part of this architecture. Where Prisma's typings and shipped JavaScript disagree, the runtime was treated as authoritative and both reported.

## The target in one page

- **The ORM boundary** is a Prisma 8 client constructed once from the committed `prisma/contract.json` — `postgres<Contract>({ contractJson, pg?, middleware, extensions })` — with **two surfaces** over it: the secured `context.db` and the **Unsafe surface** (today's `context.prisma`, renamed to state the bypass). Access enforcement stays in the engine's terminal operations. A stack-owned **tripwire** in `beforeCompile` refuses any statement executed by neither surface, reading an **ambient origin** (`AsyncLocalStorage`, `'engine' | 'unsafe'`) that each surface enters around exactly the execution it performs. [ADR-0038](../../docs/adr/0038-access-enforcement-stays-in-terminal-operations-with-the-spi-as-a-tripwire.md), [ADR-0049](../../docs/adr/0049-extension-packs-are-declared-the-tripwire-is-stack-owned.md), [ADR-0059](../../docs/adr/0059-the-engine-stamp-is-an-ambient-origin-the-executing-surface-enters.md).
- **`context.db`** becomes a **query-value surface**: `context.db.Post` (PascalCase) is an opaque wrapper over a Prisma 8 `Collection`, re-exposing a curated subset of the DSL, taking a closed **Where vocabulary**, and resolving access lazily in engine-owned terminals that materialise, honour `.select()` exactly, and return the empty value of their type on denial. Writes take scalars plus `connect` on foreign-key-owning fields and nothing nested. [ADR-0039](../../docs/adr/0039-context-db-is-a-query-value-surface-with-engine-owned-terminals.md), [ADR-0041](../../docs/adr/0041-the-secured-surface-is-an-opaque-wrapper-over-a-prisma-8-collection.md), [ADR-0046](../../docs/adr/0046-a-secured-read-materialises-and-does-not-stream.md), [ADR-0050](../../docs/adr/0050-nested-relation-input-leaves-the-secured-write-surface.md), [ADR-0055](../../docs/adr/0055-the-secured-surface-accepts-a-where-vocabulary-the-engine-lowers.md).
- **The generator** emits a standalone, fully literal TypeScript **Contract module** (no PSL, no `schema.prisma`), shells to `prisma contract emit` for the committed `contract.json` + `contract.d.ts`, seeds each declared extension pack's **contract space** under `migrations/`, and writes a four-file `.opensaas/` bundle whose `types.ts` declares only the **contract remainder** and instantiates core generics. Core derives the contract; the CLI renders it. [ADR-0040](../../docs/adr/0040-the-generator-emits-a-typescript-contract-module-not-psl.md), [ADR-0052](../../docs/adr/0052-the-generated-types-declare-the-contract-remainder-and-instantiate-core-generics.md), [ADR-0054](../../docs/adr/0054-the-generated-bundle-loads-natively-under-plain-node-from-the-committed-contract.md), [ADR-0057](../../docs/adr/0057-engine-tests-run-against-an-in-process-postgres-through-the-clients-construction-options.md), [ADR-0065](../../docs/adr/0065-the-extension-contract-space-is-a-generator-emission-and-prisma-runs-create-extension.md).
- **The migration workflow** splits on history, not provider: **dev reconciles, production migrates.** `opensaas dev` runs the stack's own in-process **Dev database** (PGlite behind `pglite-socket`), generates, runs `prisma db update`, and spawns the app; production runs `prisma db migrate` from a committed `migrations/` directory that carries the app space and every extension space. `DATABASE_URL` set means no Dev database. Prisma runs `CREATE EXTENSION` on every path. [ADR-0003](../../docs/adr/0003-deployment-uses-postgres-and-prisma-migrate.md) (amended), [ADR-0063](../../docs/adr/0063-the-dev-database-is-a-stack-run-in-process-postgres-shared-with-the-test-harness.md), [ADR-0065](../../docs/adr/0065-the-extension-contract-space-is-a-generator-emission-and-prisma-runs-create-extension.md).
- **Access-control internals** keep the two-phase read. The Access Filter becomes a typed second entry in the `Collection`'s `filters[]` and rides into every include refinement; Field Visibility stays the unconditional post-query boundary; a computed field's dependencies are an emitted one-hop set; a to-one reads as `| null` by arity; and no key reaches the ORM the Access Filter has not scoped. [ADR-0044](../../docs/adr/0044-a-read-denied-relation-is-omitted-before-the-query.md), [ADR-0051](../../docs/adr/0051-declared-dependencies-are-an-emitted-one-hop-set.md), [ADR-0058](../../docs/adr/0058-a-to-one-relation-reads-as-nullable-by-arity-not-by-column.md), [ADR-0061](../../docs/adr/0061-no-key-reaches-the-orm-the-access-filter-has-not-scoped.md).

## 1. The ORM boundary

- **One client, constructed from JSON.** `.opensaas/context.ts` imports `../prisma/contract.json` with `{ type: 'json' }` and calls `postgres<Contract>({ contractJson, … })` from `@prisma/orm-postgres/runtime`, once per process under the existing `globalThis` singleton. Not `postgres({ contract })` over the builder value: the JSON is what `db verify` signs and migrations hash, and the builder is 143 modules the server never needs. There is no generated client package and no `prisma-client/**` tree. [ADR-0054](../../docs/adr/0054-the-generated-bundle-loads-natively-under-plain-node-from-the-committed-contract.md)
- **Pool binding is `db.client`**, `{ poolOptions?, pg?: () => Pool }`, a lazy factory the generated `getPrisma()` calls after the config promise resolves. On the Dev database path the generated runtime binds `pg: new Pool({ max: 1 })` and passes `verifyMarker: false`; on a `DATABASE_URL` it passes Prisma's defaults. Adapter selection is gone with `prismaClientConstructor`. [ADR-0049](../../docs/adr/0049-extension-packs-are-declared-the-tripwire-is-stack-owned.md), [ADR-0063](../../docs/adr/0063-the-dev-database-is-a-stack-run-in-process-postgres-shared-with-the-test-harness.md)
- **Enforcement stays in the terminals; the SPI is additive.** `beforeCompile` is used only as a tripwire. RLS, per-request clients, and carrying a session through async context were each rejected on the merits. Session scoping stays the object-allocation rebind; [ADR-0012](../../docs/adr/0012-interactive-transactions-rebind-the-secured-context.md) is untouched. [ADR-0038](../../docs/adr/0038-access-enforcement-stays-in-terminal-operations-with-the-spi-as-a-tripwire.md)
- **The Engine stamp is an ambient origin.** Core owns one module — store, `withOrigin` helpers, tripwire, refusal error — that the generator emits unconditionally into the runtime client's `middleware` array and the test harness installs identically. The store holds `'engine' | 'unsafe'` and nothing else. A terminal enters it around exactly the ORM call it issues, with the `await` inside, so hooks run outside it by construction. Lazy results (`AsyncIterableResult`) are returned through a scope-preserving wrapper whose `then`/`next` re-enter the origin. Absence throws, everywhere, in every environment; a refusal inside an implicit transaction rolls it back. Measured 16/16 statement shapes at `rc.8`. [ADR-0059](../../docs/adr/0059-the-engine-stamp-is-an-ambient-origin-the-executing-surface-enters.md)
- **`prepare()` and `runtime()` are exposed on neither surface**: a prepared statement runs `beforeCompile` once at `prepare()` and never per execution, and a compiled `ExecutionPlan` handed to `runtime()` bypasses the chain. [ADR-0056](../../docs/adr/0056-app-authored-sql-lives-on-the-unsafe-surface-which-stamps-at-execution.md), [ADR-0059](../../docs/adr/0059-the-engine-stamp-is-an-ambient-origin-the-executing-surface-enters.md)
- **Extension packs are declared, not inferred.** `db.extensions: [{ name: 'pgvector', from: '@prisma/orm-extension-pgvector' }]` — import descriptors carrying the **package name**; the generator derives `/pack`, `/control` and `/runtime` per emission and fails `generate` when a subpath is missing. A plugin contributes a pack through `PluginContext.addExtension`, so `ragPlugin` names pgvector and the app never does. A field whose type needs an undeclared pack fails `generate`. [ADR-0049](../../docs/adr/0049-extension-packs-are-declared-the-tripwire-is-stack-owned.md), [ADR-0065](../../docs/adr/0065-the-extension-contract-space-is-a-generator-emission-and-prisma-runs-create-extension.md)
- **Transactions take no options.** `context.transaction(fn)` runs at Read Committed; `isolationLevel`, `maxWait`, `timeout` and `TransactionIsolationLevel` are deleted. The transaction context carries the transaction-bound secured surface (with `forUpdate()`), `advisoryLock(key)`, and the transaction-bound Unsafe surface. [ADR-0042](../../docs/adr/0042-transactions-lose-isolation-levels-and-errors-become-stack-owned.md), [ADR-0047](../../docs/adr/0047-a-row-lock-is-an-engine-owned-two-statement-terminal.md), [ADR-0056](../../docs/adr/0056-app-authored-sql-lives-on-the-unsafe-surface-which-stamps-at-execution.md)
- **Errors are stack-owned.** Driver errors are normalised at the engine terminals and at the transaction owner's commit (before the deferred-hook flush): SQLSTATE `40001` → `SerializationFailure`, `23505` → a unique-violation error with per-field messages resolved through a **generated constraint map** (constraint name → field names). Each ships an `is*` predicate. `DatabaseError.code` is removed; **no `P####` literal survives anywhere in the repo**, enforced mechanically. The Unsafe surface yields raw driver errors. [ADR-0042](../../docs/adr/0042-transactions-lose-isolation-levels-and-errors-become-stack-owned.md)
- **Core exports the access-filter builder** as supported API, so no package carries a copy of `checkAccess`/`mergeFilters`. [ADR-0038](../../docs/adr/0038-access-enforcement-stays-in-terminal-operations-with-the-spi-as-a-tripwire.md)

## 2. `context.db`, the secured surface

- **Shape.** A query is an immutable value; nothing is enforced until a terminal runs it. `context.db.<List>` is an opaque wrapper holding a `Collection` privately — a subclass cannot hide Prisma's own terminals, so only a wrapper makes "you cannot execute an unscoped query" a fact about the types. Keys are PascalCase (`context.db.AuthUser`); `getDbKey()` is deleted. The surface is parameterised by the generated `Contract`; `PrismaClientLike = any` is deleted. [ADR-0039](../../docs/adr/0039-context-db-is-a-query-value-surface-with-engine-owned-terminals.md), [ADR-0041](../../docs/adr/0041-the-secured-surface-is-an-opaque-wrapper-over-a-prisma-8-collection.md)
- **Read subset.** `where`, `select`, `orderBy`, `limit`, `offset`, `cursor`, `distinct`/`distinctOn`, `include` (its refinement yields a nested wrapper), `combine`, `aggregate`; terminals `all()`, `first()`, `aggregate(...)`; plus `nearest()` and, on a transaction-bound builder only, `forUpdate()`. `groupBy`, the `*All` family, `*AndCount`, `upsert`, `createMany`/`updateMany` and streaming are out. A method appears only if the engine knows how to scope it; omission is the signal. [ADR-0041](../../docs/adr/0041-the-secured-surface-is-an-opaque-wrapper-over-a-prisma-8-collection.md), [ADR-0045](../../docs/adr/0045-vector-search-is-an-engine-owned-terminal-over-a-native-vector-column.md), [ADR-0047](../../docs/adr/0047-a-row-lock-is-an-engine-owned-two-statement-terminal.md)
- **Where vocabulary.** `where`/`orderBy` take a closed, data-shaped grammar the engine owns — `equals`, `not`, `in`, `notIn`, `lt`, `lte`, `gt`, `gte`, `contains`; `AND`/`OR`/`NOT`; `some`/`every`/`none` on a relation of any cardinality — lowered onto Prisma's lambda in one place, **total or throwing, `sudo` included**. `contains` is engine-owned, escapes `%`/`_`/`\`, and lowers to `ILIKE` (case-insensitive is a deliberate meaning change). A relation predicate carries the related list's `query` access inside the `EXISTS`; denied means empty set. `orderBy` is scalar-only. The access filter is a second `filters[]` entry the `Collection` ANDs natively — nobody hand-merges. [ADR-0055](../../docs/adr/0055-the-secured-surface-accepts-a-where-vocabulary-the-engine-lowers.md)
- **Terminals materialise.** `.all()` is `Promise<T[]>`; no terminal is an async iterable. Partial delivery would defeat atomic denial, a re-entrant `resolveOutput` read would deadlock the single-connection dev loop, and the include path materialises parents anyway. A caller needing a cursor uses the Unsafe surface. Memory is bounded by result size; bounding a read is the caller's job. [ADR-0046](../../docs/adr/0046-a-secured-read-materialises-and-does-not-stream.md)
- **Exact selection with widen-and-strip.** A terminal's result matches the caller's `.select()` exactly. The engine widens for each computed field's emitted dependency set and for field-access resolution, then strips `widened ∖ caller` as a recursive set difference. [ADR-0041](../../docs/adr/0041-the-secured-surface-is-an-opaque-wrapper-over-a-prisma-8-collection.md), [ADR-0051](../../docs/adr/0051-declared-dependencies-are-an-emitted-one-hop-set.md)
- **Denial returns the empty value of the terminal's type**: `[]` from `all`, `null` from `first`/`create`/`update`/`delete`, `0` from a count. On the include path a to-one the related list's `query` access scopes away is `null` and a to-many `[]`, by arity alone; an outright `false` lowers to a never-matching refinement predicate so the key is present, never absent. A required to-one is required to write and nullable to read. [ADR-0041](../../docs/adr/0041-the-secured-surface-is-an-opaque-wrapper-over-a-prisma-8-collection.md), [ADR-0058](../../docs/adr/0058-a-to-one-relation-reads-as-nullable-by-arity-not-by-column.md)
- **Write subset.** `create(data)`, `where(...).update(data)`, `where(...).delete()`. A payload holds scalars plus **`connect`**, legal only on the field that owns the foreign key, where it lowers to the engine's reachability query (target `query` access ANDed with the criterion) and a scalar FK write — three statements at the database, all inside the terminal's origin. Assigning `null` replaces `disconnect`. No nested `create`/`update`/`delete`/`connectOrCreate`/`set`/`updateMany`/`deleteMany`; `packages/core/src/context/nested-operations.ts` is deleted. A caller writing several rows atomically authors them inside `context.transaction`. Every write still opens a transaction. A required-foreign-key cycle is unwritable through the secured surface and addressed on the Unsafe surface. [ADR-0050](../../docs/adr/0050-nested-relation-input-leaves-the-secured-write-surface.md)
- **Row lock.** `txContext.db.<List>.where(…).forUpdate().first()` / `.all()`: the scoped ORM read runs first, then an engine-composed `SELECT <pk> FROM <table> WHERE <pk> IN ($1…$n) ORDER BY <pk> LIMIT $n+1 FOR UPDATE` through the contract-bound raw tag (Prisma quotes identifiers, binds each key with the identity column's codec, executes on the transaction's connection; the stack authors only the clause text). No keys, no statement. `all().forUpdate()` refuses a key set over a named constant. A terminal never returns a row it did not lock. `NOWAIT`/`SKIP LOCKED`/`forShare` stay out. `advisoryLock(key)` is `pg_advisory_xact_lock(hashtext($1))` through `tx.execute()`. [ADR-0047](../../docs/adr/0047-a-row-lock-is-an-engine-owned-two-statement-terminal.md), [ADR-0062](../../docs/adr/0062-the-row-lock-statement-is-composed-by-the-engine-over-the-orms-raw-lane.md)
- **Vector search.** `context.db.Article.where(…).nearest('embedding', vector, { limit, minScore })` is a core-owned terminal over a native `Vector(n)`/`halfvec` column, returning `{ item, score }` (the one exception to exactness), with the access filter injected into the vector query and `minScore` lowered to a distance bound. Searching requires read access to the embedding field. [ADR-0045](../../docs/adr/0045-vector-search-is-an-engine-owned-terminal-over-a-native-vector-column.md)
- **Types.** `Row`, `StoredRow`, `CreateInput`, `UpdateInput`, `SecuredList`, `StackBaseContext`, `StackContext`, `StackTransactionContext` are core generics keyed by `Contract` and the generated `Remainder`. `CreateInput` is both the export and the terminal's parameter (#608 closes by deletion). Include narrowing derives `Row<Target> | null` for `'1:1' | 'N:1'` and `Row<Target>[]` otherwise from the contract's relation graph, never from Prisma's `IncludeRelationValue`. Every generic the bundle instantiates resolves to an object type ([ADR-0032](../../docs/adr/0032-generated-context-and-customdb-are-interfaces-not-type-aliases.md)'s interface rule). [ADR-0052](../../docs/adr/0052-the-generated-types-declare-the-contract-remainder-and-instantiate-core-generics.md), [ADR-0058](../../docs/adr/0058-a-to-one-relation-reads-as-nullable-by-arity-not-by-column.md)
- **Bare read, One hop, Projection** are ORM natives; [ADR-0024](../../docs/adr/0024-a-read-with-no-include-fetches-scalars-not-relations.md) and [ADR-0026](../../docs/adr/0026-naming-a-relation-fetches-its-columns-not-its-subtree.md) are withdrawn, `READ_INCLUDE_MAX_DEPTH` keeps its job as a fail-closed cost limit over the caller's tree (the dependency-set widening is exempt), and One hop holds on both sides of a one-to-one with no exception. [ADR-0043](../../docs/adr/0043-bare-read-and-one-hop-become-the-orms-not-ours.md), [ADR-0064](../../docs/adr/0064-one-hop-holds-on-both-sides-of-a-one-to-one-and-the-generator-emits-the-pair.md)

## 3. The Unsafe surface

- The deliberately unsecured client under a name that states the bypass. The identifier is the build's to fix; `context.prisma` is the thing renamed. Its consumers: core's own internals, the Auth adapter, and application scripts. [ADR-0038](../../docs/adr/0038-access-enforcement-stays-in-terminal-operations-with-the-spi-as-a-tripwire.md)
- It carries Prisma's typed SQL builder (`sql`) and raw tag (`raw`) untouched, owns the executors `query(plan)` (returns Prisma's `AsyncIterableResult`) and `execute(plan)`, and its ORM lane is a transparent `Proxy` over Prisma's `orm`. Each enters the unsafe origin around the execution it performs; a plan or query value is unmarked until the surface runs it and no application writes a mark. Neither the bare client nor `prepare()`/`runtime()` is reachable. No curated subset; total fidelity with the cost stated — no access filter, no Field Visibility, no `resolveOutput`, no hooks, raw errors. [ADR-0056](../../docs/adr/0056-app-authored-sql-lives-on-the-unsafe-surface-which-stamps-at-execution.md), [ADR-0059](../../docs/adr/0059-the-engine-stamp-is-an-ambient-origin-the-executing-surface-enters.md)
- It has a transaction-bound shape reached from the transaction context (Prisma's `tx` carries no `raw`; the surface closes over the client's raw lane and runs plans through `tx.query`). [ADR-0056](../../docs/adr/0056-app-authored-sql-lives-on-the-unsafe-surface-which-stamps-at-execution.md)
- Prisma's raw guardrails (`lints()`/`budgets()`) are opt-in middleware; the generated client installs neither. [ADR-0062](../../docs/adr/0062-the-row-lock-statement-is-composed-by-the-engine-over-the-orms-raw-lane.md)
- The secured surface gains no SQL escape of any kind — no `fns.raw` in `where()`, no `sql()` terminal. [ADR-0056](../../docs/adr/0056-app-authored-sql-lives-on-the-unsafe-surface-which-stamps-at-execution.md)

## 4. Generator output

`pnpm generate` keeps its name and becomes: evaluate the config → `deriveContract(config)` in core (from the field builders' structured type descriptors) → the CLI renders the **Contract module** and `prisma.config.ts` → the CLI seeds every declared pack's **extension contract space** via `runContractSpaceSeedPhase` from `@prisma/orm-toolchain/cli/control-api` → the CLI shells to `prisma contract emit --output-path prisma/` → the CLI writes the `.opensaas/` bundle. CI re-runs generation and fails on a dirty tree covering `contract.json`, `contract.d.ts`, and `migrations/<space>/**` plus the space's snapshot.

- **Contract module.** Standalone and fully literal — imports nothing from the config, so the builder's purity rules hold by construction. PSL is not emitted, not even as a reference. `extendPrismaSchema` and its field-level `{ fkLine, relationLine }` sibling are dropped in favour of first-class options: namespaces, extension packs, typed `onDelete`/`onUpdate` over the five referential actions, output paths in `prisma.config.ts`. [ADR-0040](../../docs/adr/0040-the-generator-emits-a-typescript-contract-module-not-psl.md)
- **Contract artifacts.** `prisma/contract.json` + `prisma/contract.d.ts`, committed, byte-deterministic. The `.d.ts` carries `FieldOutputTypes`/`FieldInputTypes`, per-field nullability and codec, the column map and the relation graph, so nothing downstream re-derives them. [ADR-0040](../../docs/adr/0040-the-generator-emits-a-typescript-contract-module-not-psl.md), [ADR-0052](../../docs/adr/0052-the-generated-types-declare-the-contract-remainder-and-instantiate-core-generics.md)
- **`prisma.config.ts`** becomes `definePrismaConfig({ orm: ormConfig({ contract, extensions, db: { connection: resolveDatabaseUrl() } }) })`, importing each pack's `/control` descriptor and never the app config. `ormConfig.extensions` is required. [ADR-0040](../../docs/adr/0040-the-generator-emits-a-typescript-contract-module-not-psl.md), [ADR-0063](../../docs/adr/0063-the-dev-database-is-a-stack-run-in-process-postgres-shared-with-the-test-harness.md), [ADR-0065](../../docs/adr/0065-the-extension-contract-space-is-a-generator-emission-and-prisma-runs-create-extension.md)
- **Extension contract space.** Five committed files per declared pack under `migrations/` (`<space>/<package>/{migration.json,ops.json}`, `<space>/refs/head.json`, the snapshot), regenerated on every `generate`; a pack upgrade shows up as a generate diff. The root `.gitignore`'s `prisma/migrations/` line goes. [ADR-0065](../../docs/adr/0065-the-extension-contract-space-is-a-generator-emission-and-prisma-runs-create-extension.md)
- **The Generated bundle.** `.opensaas/context.ts`, `types.ts`, `lists.ts`, `plugin-types.ts` — none of them Prisma's, erasable TypeScript by contract (checked under `erasableSyntaxOnly` + `verbatimModuleSyntax` in the CLI's tests), explicit `.ts` import extensions, alias-free value imports, loadable by the host bundler and by plain Node ≥ 22.18 with no compiled twin. The **Node build** (`output.buildTarget`, `node-build.ts`, `.opensaas/dist/`, `@typescript/native`) is deleted. Two emitted data tables also ride in the bundle — the **declared dependency set** table (per `(list, field)`, with each list's actual system fields) and the **constraint map** — reached through the generated context; where they sit within the bundle is the build's. [ADR-0054](../../docs/adr/0054-the-generated-bundle-loads-natively-under-plain-node-from-the-committed-contract.md), [ADR-0051](../../docs/adr/0051-declared-dependencies-are-an-emitted-one-hop-set.md), [ADR-0042](../../docs/adr/0042-transactions-lose-isolation-levels-and-errors-become-stack-owned.md)
- **`types.ts` authors the contract remainder only** — per list `{ computed, output, input, needs, singleton? }` — and instantiates named interfaces (`Post`, `PostCreateInput`, `PostUpdateInput`, `PostList`, `DB`, `Context`, `BaseContext`, `TransactionContext`) over core's generics. Every `{List}Find*Args`/`*Args`/`GetPayload`/`Select`/`Include`/`VirtualFields`/`TransformedFields`/`Output`/`WhereInput`/legacy `Hooks` type is deleted; `{List}Crud` is renamed. `lists.ts` keeps `Lists.<List>.TypeInfo` with `item` (stored row), `output`, `inputs`, and per-field `needs` facts; a `resolveOutput` hook's `item` is `Pick<StoredRow, needs | system>`. App-facing names survive. [ADR-0052](../../docs/adr/0052-the-generated-types-declare-the-contract-remainder-and-instantiate-core-generics.md)
- **The field-builder contract is replaced, not translated.** `getPrismaType`/`getPrismaColumns`/`getPrismaRelation` become a contract-shaped method returning a structured type descriptor (`{ pack, type, args }`), native type, nullability and column mapping; `getTypeScriptType`/`getTypeScriptImports`/`resultExtension`/`VirtualField.outputType` become `outputType?`/`inputType?: TypeDescriptor`; `needs` accepts stored-column keys and is refused on a field with no `resolveOutput`. Every third-party field package moves. [ADR-0040](../../docs/adr/0040-the-generator-emits-a-typescript-contract-module-not-psl.md), [ADR-0049](../../docs/adr/0049-extension-packs-are-declared-the-tripwire-is-stack-owned.md), [ADR-0051](../../docs/adr/0051-declared-dependencies-are-an-emitted-one-hop-set.md), [ADR-0052](../../docs/adr/0052-the-generated-types-declare-the-contract-remainder-and-instantiate-core-generics.md)
- **Config surface.** `db.provider` (postgresql only); `db.idField: 'uuid7' | 'cuid2' | 'int autoincrement'` per list over a config default (`uuid7` default; singletons derive `Int @id @default(1)` and refuse `db.idField`; plugin-injected lists pin their own); `db.extensions`; `db.client`; `db.indexes` minus `sort` (a generate-time error) with named entries as `name:`; `db.timestamps` off by default. `createdAt`/`updatedAt` go through `field.temporal.*`, `updatedAt` application-side with no database backstop. A one-to-one is two `many: false` declarations; the owner (by `db.foreignKey`, else alphabetical, else field name) emits the FK column, `constraints.foreignKey`, a **unique constraint** and `rel.belongsTo`, the other side `rel.hasOne({ by })`. Implicit many-to-many is a generation error; the app authors a junction list with a surrogate id and a unique pair index. The id type is per list, read from `contract.d.ts`, with one contract-driven boundary coercion for admin URLs, MCP arguments and generated Zod schemas. [ADR-0048](../../docs/adr/0048-the-deleted-psl-constructs-become-config-defaults-not-ddl.md), [ADR-0064](../../docs/adr/0064-one-hop-holds-on-both-sides-of-a-one-to-one-and-the-generator-emits-the-pair.md), [ADR-0040](../../docs/adr/0040-the-generator-emits-a-typescript-contract-module-not-psl.md)
- **Generate-time refusals the build must implement**, each naming the list, the entry and the fix: `db.indexes` `sort`; `many: true` on both sides; `db.idField` on a singleton; a field type needing an undeclared pack; a pack missing a required subpath; duplicate pack `name` with differing `from`; `needs` on a hookless field; `db.isNullable: false` or a `db.indexes` entry on the non-owning side of a one-to-one; `db.foreignKey: true` on both sides; a relationship pointing at a composite-keyed list (out of scope, refused in advance); the emitted contract's relations disagreeing with the config-derived graph.
- **Test strategy for the generator.** The Contract module is snapshotted as deterministic output; the rendered module and the programmatic `deriveContract` must emit identical contract JSON; a few representative configs run real emission and assert structurally. Column-padding and attribute-ordering assertions cease to exist. [ADR-0040](../../docs/adr/0040-the-generator-emits-a-typescript-contract-module-not-psl.md), [ADR-0057](../../docs/adr/0057-engine-tests-run-against-an-in-process-postgres-through-the-clients-construction-options.md)

## 5. Migration workflow and the dev loop

- **`opensaas dev` is the loop.** Start the Dev database (core's `startDevDatabase({ dataDir, extensions, maxConnections })` — in-process PGlite behind a `pglite-socket` server on a free loopback port, state file at `.opensaas/dev-db.json`), `generate`, `prisma db update`, spawn the app (`next dev` by default, `opensaas dev -- <command>` otherwise) with **no `DATABASE_URL` injected**, and watch `opensaas.config.ts`. On change, generation is **staged behind reconciliation**: emit to staging, plan `db update`, promote contract and bundle only after the plan applies. A destructive plan on boot stops at Prisma's consent prompt; mid-session it leaves bundle and database at the previous schema, prints the plan and the `pnpm db:update` instruction, and keeps serving. `pnpm db:update` is the stack's promoting `opensaas db update`, run _during_ `dev`, and errors when nothing is listening. The loop restarts the app child after a destructive promote (a cached client survives HMR). CLI spawns are async with stdin closed (`stdio: ['ignore', …]`). Foreground sidecar: no daemon, no registry, no reset command — reset is deleting `.opensaas/dev-db/`. [ADR-0063](../../docs/adr/0063-the-dev-database-is-a-stack-run-in-process-postgres-shared-with-the-test-harness.md), [ADR-0065](../../docs/adr/0065-the-extension-contract-space-is-a-generator-emission-and-prisma-runs-create-extension.md)
- **Discovery is one rule.** `resolveDatabaseUrl()` in core returns the URL and its provenance (`'env' | 'dev-database'`): `DATABASE_URL` if set, else the sidecar's state file, else a throw naming both remedies. `verifyMarker: false` and the single-connection pool apply on `'dev-database'` provenance only. Ports are never fixed; twelve examples under root `pnpm dev` each get their own. [ADR-0063](../../docs/adr/0063-the-dev-database-is-a-stack-run-in-process-postgres-shared-with-the-test-harness.md)
- **Cold start is `create` then `dev`.** The scaffolder's post-step shrinks to install and `generate`; the first `pnpm dev` creates and reconciles the database. [ADR-0063](../../docs/adr/0063-the-dev-database-is-a-stack-run-in-process-postgres-shared-with-the-test-harness.md)
- **Production migrates.** `prisma db migrate` from the committed `migrations/` directory: app migration packages (`migration plan`, graph edges keyed on SHA-256 contract hashes; a generated contract is first-class) and each extension space's package. `db update` also writes the `db` ref under `migrations/app/refs/`. [ADR-0003](../../docs/adr/0003-deployment-uses-postgres-and-prisma-migrate.md) (amended by #1040, ADR-0063, ADR-0065)
- **Extensions.** Prisma runs `CREATE EXTENSION IF NOT EXISTS` from the pack's contract space on every path — first `opensaas dev`, CI's `db update`, production's `db migrate` — skipping a pre-installed extension and failing cleanly (`58P01`, `failingSpace`) on a server without it. The deployment's job is provisioning: make the extension available and give the migrating role the privilege (pgvector is untrusted) or pre-create it. No stack-run DDL, no hand step on the route. [ADR-0065](../../docs/adr/0065-the-extension-contract-space-is-a-generator-emission-and-prisma-runs-create-extension.md)
- **The Database escape.** `DATABASE_URL` set means no Dev database, for one purpose: a Postgres the stack does not own, chosen for parity or contention. CI keeps service containers on parity, on a pgvector-capable Postgres 17 image; the nightly cold-clone job is where CI exercises the sidecar. Windows is provisionally on the escape pending a run on Windows. [ADR-0063](../../docs/adr/0063-the-dev-database-is-a-stack-run-in-process-postgres-shared-with-the-test-harness.md)

## 6. Access-control internals

- **The two-phase read survives.** Field-level `read` denial does not become a projection for scalars (a second interpreter of one rule kind, for a saving that evaporates on any row-dependent rule). Field Visibility keeps four jobs — strip unreadable fields, run `resolveOutput`, compute virtual fields, and the include-path nulling now done natively — and stays the unconditional boundary: a missed pre-query omission is a performance regression, never a leak. [ADR-0044](../../docs/adr/0044-a-read-denied-relation-is-omitted-before-the-query.md), [ADR-0001](../../docs/adr/0001-access-control-is-a-two-phase-read.md) (amended in scope)
- **The Access Filter** merges as typed `CollectionState` composition — the access filter is a `filters[]` entry — and scopes includes as refinement `where`s carrying the related list's `query` access. It omits, before the query, a relation whose own field-level `read` rule is **row-independent** and denies, except a relation in a live declared dependency set. `toOneAccessFilters`, `resolveToOneAccessVisibility` and the post-query null-forcing are deleted: Prisma scopes a to-one refinement natively and decodes an empty scope to `null` without dropping the parent. [ADR-0039](../../docs/adr/0039-context-db-is-a-query-value-surface-with-engine-owned-terminals.md), [ADR-0044](../../docs/adr/0044-a-read-denied-relation-is-omitted-before-the-query.md), [ADR-0051](../../docs/adr/0051-declared-dependencies-are-an-emitted-one-hop-set.md), [ADR-0058](../../docs/adr/0058-a-to-one-relation-reads-as-nullable-by-arity-not-by-column.md)
- **One classifier, four consumers.** The row-independent-rule classifier (poisoned `item`/`inputData` Proxy) is interpreted in exactly one place; its consumers differ deliberately in what they do with the answer: a predicate throws ([ADR-0031](../../docs/adr/0031-a-predicate-cannot-name-a-field-the-session-cannot-read.md)), an include omits ([ADR-0044](../../docs/adr/0044-a-read-denied-relation-is-omitted-before-the-query.md)), MCP's read and write vocabularies omit ([ADR-0053](../../docs/adr/0053-the-mcp-vocabulary-omits-what-a-row-independent-rule-denies.md)). None is harmonised into another.
- **No key reaches the ORM the Access Filter has not scoped, and none that key validation has not resolved.** The general rule under #566, #1082, #1087, #1088 and #1092; the build checks every new surface against it — nested `where`/`orderBy` inside an include refinement, a caller-supplied count reducer, any key the list config never declared. [ADR-0061](../../docs/adr/0061-no-key-reaches-the-orm-the-access-filter-has-not-scoped.md)
- **Declared dependencies.** `needs` names stored columns and relations; the set is resolved at generation, emitted, one hop and non-transitive (no computed field runs on a declared-only branch, so no cycle can exist and `validateNeedsClosureDepth` is deleted); a declaration outranks a caller-facing `read` denial (the value reaches the hook and is stripped before the caller); a hook sees its declared set plus the list's system fields and nothing else. `READ_INCLUDE_MAX_DEPTH` exempts the widening. [ADR-0051](../../docs/adr/0051-declared-dependencies-are-an-emitted-one-hop-set.md), [ADR-0025](../../docs/adr/0025-a-computed-field-declares-the-relations-it-needs.md) and [ADR-0027](../../docs/adr/0027-a-computed-field-runs-only-when-it-is-going-to-be-returned.md) (amended)
- **The Write Pipeline** keeps its order — operation access outside the transaction → `resolveInput` → `validate` → built-in rules → writable-field filtering → relationship resolution (the `connect` reachability query and FK write) → persistence → after-hooks → Field Visibility — with the nested-operations phase gone. `write-pipeline.ts`'s `$transaction`-absence branch is deleted (no client lacking `transaction` can be constructed). [ADR-0028](../../docs/adr/0028-a-transaction-boundary-hook-reports-the-outermost-transaction.md) is untouched but for its enumerator. [ADR-0050](../../docs/adr/0050-nested-relation-input-leaves-the-secured-write-surface.md), [ADR-0057](../../docs/adr/0057-engine-tests-run-against-an-in-process-postgres-through-the-clients-construction-options.md)
- **Relationship-row removal** across an explicit junction deletes the junction row, gated on the junction list's own delete access; a to-one back-reference is nulled. `removeAction: 'delete'` keeps its meaning. [ADR-0018](../../docs/adr/0018-relationship-table-row-removal-disconnects-by-default.md) (amended by ADR-0048, ADR-0050)
- **Silent failure**, the resolve-chain cycle guard ([ADR-0023](../../docs/adr/0023-the-resolve-chain-is-bounded-by-a-cycle-guard.md)), fail-closed scoping ([ADR-0022](../../docs/adr/0022-access-control-fails-closed-when-it-cannot-scope.md)), the predicate-time read check ([ADR-0031](../../docs/adr/0031-a-predicate-cannot-name-a-field-the-session-cannot-read.md)), policy authorship ([ADR-0013](../../docs/adr/0013-access-control-belongs-to-the-application-not-plugins.md)) and the interactive-transaction rebind ([ADR-0012](../../docs/adr/0012-interactive-transactions-rebind-the-secured-context.md)) all stand.

## 8. Testing

- Engine tests assert on behaviour through the secured surface against an **in-process PGlite per Vitest file** (schema applied once through the control client, truncate per test), honouring the `DATABASE_URL` escape for the identical suite. A **recording `beforeCompile`** beside the engine's stamp gives plan-level assertions where the built query is the subject; SQL text is never asserted. No test-only seam on the wrapper; the harness always installs the tripwire. The fake `pg` driver works and is not admitted. PGlite, `pglite-socket` and `pglite-pgvector` are optional peers of core and dev dependencies of every package with a suite. [ADR-0057](../../docs/adr/0057-engine-tests-run-against-an-in-process-postgres-through-the-clients-construction-options.md), [ADR-0063](../../docs/adr/0063-the-dev-database-is-a-stack-run-in-process-postgres-shared-with-the-test-harness.md), [ADR-0065](../../docs/adr/0065-the-extension-contract-space-is-a-generator-emission-and-prisma-runs-create-extension.md)

## 14. Costs taken knowingly

Stated so the build's documentation says them rather than a user discovering them. Each is a decision, not a defect.

- `updatedAt` is application-side: a write that bypasses the ORM (`psql`, `db update`, the Unsafe surface) leaves it stale, and `update({})` no longer moves it. (ADR-0048)
- `needs: ['passwordHash']` is a real, greppable leak channel owned by whoever writes it; a declaration outranks a read denial. (ADR-0051)
- A `resolveOutput` hook reading an undeclared column breaks silently unless typed through `Lists.<List>.TypeInfo`, where it is a compile error. A declared-only branch computes nothing. Two hops cost a privileged read. (ADR-0051, 0052)
- Every to-one read off an included row is a null-check, `NOT NULL` column or not. (ADR-0058)
- A secured read holds its whole result; a large read is bounded by the caller. (ADR-0046)
- A row lock is two round trips; `all().forUpdate()` is bounded; `hashtext` collisions on `advisoryLock` cost spurious serialisation, never a missed lock. (ADR-0047, 0062)
- A required-foreign-key cycle is unwritable through the secured surface. (ADR-0050)
- `contains` and text `eq` in filter URLs become case-insensitive; a to-many count filter other than presence degrades to free text; sorting by a to-many count is gone. (ADR-0055)
- An approximate HNSW scan under a selective access filter can return fewer than `limit` rows; exactness holds under an exact scan and is bounded by the iterative-scan budget otherwise. (ADR-0045)
- `aggregate`'s count throws beyond ±(2^53 − 1). (ADR-0041)
- The Auth adapter implements no joins and no `createSchema`; better-auth's `generate`/`migrate` CLI is unsupported; a raced unique violation surfaces raw. (ADR-0060)
- A hand-managed index the generator did not emit gets no per-field unique-violation messages. (ADR-0042)
- pgvector needs superuser or a provider grant on the migrating role, or a DBA pre-creates it. (ADR-0065)
- `pnpm db:update` requires the dev loop to be running; a destructive mid-session change restarts the app. (ADR-0063)
