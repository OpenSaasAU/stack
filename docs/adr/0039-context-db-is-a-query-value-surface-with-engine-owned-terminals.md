# context.db is a query-value surface with engine-owned terminals

`context.db` today is a Prisma 7-shaped method surface — `findUnique` / `findMany` / `findFirst` / `create` / `update` / `delete` / `count` — with Keystone-flavoured semantics layered on top. Under Prisma 8 it becomes a **query-value surface** mirroring the ORM's own DSL, where a query is built up as an immutable value and executed by a terminal operation the engine owns. The shape follows Prisma; the terminals do not.

The reason to move is that [#1031](https://github.com/OpenSaasAU/stack/issues/1031) found a query is a **value, not a fluent executor**: `Collection` is immutable and carries an exported `CollectionState`. Filter merging — the operation the Access Filter exists to perform — therefore survives in typed form rather than as object-spreading into a `where` bag. Bare read, one hop and projection (ADR-0024, ADR-0026, ADR-0027) stop being behaviours our engine hand-implements and become ORM natives that already do what those records decided. Keeping the Prisma 7 façade would mean maintaining an emulation of semantics the ORM below now provides, and hiding the one type that makes filter merging checkable.

The terminals stay ours because the guarantees are ours. Prisma has no notion of returning `null` because a session was denied, and it never will. Silent failure is a security property — it is what stops a caller distinguishing "denied" from "does not exist" — so the operation that executes a query has to be the operation that resolved access, merged the filter and filtered the fields. That is the same boundary ADR-0038 keeps enforcement at, seen from the caller's side.

Not every current guarantee earns the trip. `findUnique` requiring a unique `where` (#565) and singleton lists using `get()` are shapes the **old method surface** forced: both exist because a method name had to carry a distinction the call could not otherwise express. A query-value DSL expresses those distinctions structurally, so they are re-derived from the new surface rather than ported as method names. Silent failure is the opposite case — it is not a shape, it is a rule about what a denied read returns, and it survives unchanged.

## Considered Options

- **Keep the Prisma 7-shaped façade and swap Prisma 8 underneath.** The lowest-churn option, and the one ADR-0032 (generated context is an interface) makes cheapest to hold. Rejected because it commits the engine to re-implementing bare read, one hop and projection against an ORM that now provides them, and it puts a method surface in front of `CollectionState`, discarding the typed filter merging that made this migration tractable in the first place.
- **Expose both surfaces**, façade for continuity and query-value for new code. Rejected: two secured surfaces must agree on every guarantee forever, and each is a place the other's invariants can be forgotten. The project has no external users and has already accepted breaking changes freely, so continuity buys nothing here worth that.
- **Adopt Prisma's terminals as well as its shape.** Rejected. It would delete silent failure, since Prisma's own terminals cannot express denial as absence, and silent failure is a security property rather than an ergonomic one.
- **Port `findUnique`-requires-unique and singleton `get()` verbatim.** Rejected as carrying Prisma 7-era shapes into a surface that no longer needs them; the distinctions they encode are structural in the new DSL. The _guarantees_ are not being dropped — a non-unique single-row lookup is still not a unique lookup — only the method names that were their only available expression.
- **Drop silent failure along with the other two**, letting Prisma's semantics stand throughout. Rejected outright: it leaks row existence, which is the thing the convention exists to prevent.

## Consequences

- **This is a breaking change to the primary application-facing API**, and the largest single one in the Prisma 8 migration. Every example and every consumer moves. It ships as a minor with the break named in the changeset, per the project's pre-1.0 convention.
- **The Access Filter's merge step becomes typed `CollectionState` composition** rather than `where`-object spreading, so a merge that produces an incoherent filter can fail at compile time rather than at query time.
- **ADR-0024, ADR-0026 and ADR-0027 keep their decisions and lose their implementations.** Bare read, one hop and projection are what the ORM does natively; the records stand as statements of intent, and the engine code enforcing them goes away. What must be verified at GA is that the natives agree with the records in every case they cover, not merely in the common one.
- **Silent failure is now a property of the terminal operations specifically**, and is the reason they cannot be delegated to Prisma. Any future terminal added to this surface inherits that obligation.
- **`findUnique`/`findFirst` and singleton `get()` need re-derivation, not translation.** The build effort has to establish how the new DSL expresses "this lookup must be unique" and "this list holds one row" before the surface is settled; #565's reasoning is the input, not the answer.
- **ADR-0032 is unaffected in principle but not in content.** The generated context stays an interface; what that interface declares changes completely.
- **Whether the two-phase read survives is a separate decision**, now unblocked by this one: Prisma 8's native projection raises the possibility that field-level access is expressible on the query rather than as a post-hoc walk, which would collapse Field Visibility into the Access Filter. That turns on ADR-0001 and ADR-0022 and is recorded elsewhere.
