# The secured surface is an opaque wrapper over a Prisma 8 Collection

[ADR-0039](0039-context-db-is-a-query-value-surface-with-engine-owned-terminals.md) decided that `context.db` becomes a query-value surface with terminals the engine owns. It did not say how that surface is constructed, which methods it carries, or what its terminals return — and it explicitly left several of those to "the build effort". This record closes them: `context.db.<List>` is an **opaque wrapper** holding a Prisma 8 `Collection` privately, re-exposing a curated subset of the DSL, resolving all access lazily in terminals that are the only way to execute.

The wrapper is opaque because Prisma's terminals cannot be taken away. A `Collection` subclass cannot hide `all()`, `first()` or `aggregate()`: making a terminal `private` is a `TS2415`, redeclaring it incompatibly is a `TS2416`, and removal is not expressible in TypeScript inheritance at all. Worse for the subclass approach, builder methods declare their return type as the base `Collection` rather than `this`, so after a single chaining step the subclass's own members are gone from the static type while the runtime instance is still the subclass. A subclass is an additive convenience, never a restricting wrapper — so a subclassed `context.db` would leave an unsecured `.all()` one keystroke from correct-looking code, caught by ADR-0038's tripwire at runtime rather than by the compiler. Since that tripwire is deliberately deletable if the SPI churns, a design that leans on it for its primary guarantee would make it undeletable. Only a wrapper that never hands out a `Collection` makes "you cannot execute an unscoped query" a fact about the types.

Access resolves **lazily, entirely in the terminal**. Builder methods are synchronous and access rules are `async`, so resolving eagerly per builder call would make the whole DSL awaited. Lazy resolution also keeps ADR-0038's claim literally true — one place resolves operation access, merges the filter, filters the fields, and applies the engine stamp. That stamp has a real home: Prisma's annotations are written through a `configure` callback on each terminal (`all((meta) => meta.annotate(...))`) rather than a chainable method, which is exactly where the access work already happens.

## Decisions

- **A method appears on the secured surface only if the engine knows how to scope it.** Omission is the signal, and a missing method is a compile error rather than a silent hole.
- **Read subset:** `where`, `select`, `orderBy`, `limit`, `offset`, `cursor`, `distinct`/`distinctOn`, `include`, `combine`, and `aggregate`. `include`'s refinement callback yields a **nested wrapper**, not a nested `Collection`, or the boundary has a hole one level down.
- **`aggregate` is in, `groupBy` is out.** `aggregate` is load-bearing — there is no `.count()` terminal in Prisma 8, so it is the only way to count, and scoped counts are a guarantee (below). It carries forward today's `count` obligations: reject a `where` key the list config does not declare, reject one naming a field this session cannot read, then merge the access filter. `groupBy` is the case the principle above was written for: field visibility over grouped rows is meaningless, and group cardinality over a scoped set leaks the shape of denied data.
- **Write subset: `create`, `update`, `delete` only.** `update` and `delete` are terminals on a composed query — `where(...).update(...)` — because they are inherently scoped operations whose access filter merges into the same predicate as a read's. `create` has no scope to compose (Prisma's `INSERT` has no `withWhere`, and create access must return a boolean since there is no row to scope against) and stays a plain method.
- **`createAll`/`updateAll`/`deleteAll`, the `*AndCount` family, and `upsert` are excluded.** The `*All` family cannot fire per-row hooks or resolve access per row, and a loop wearing a bulk name is what the subset principle exists to prevent. This **drops today's `createMany`/`updateMany`**, which are already loops (`packages/core/src/context/index.ts:1352`, `:1400`) — the convenience goes, the capability does not. `*AndCount` returns a count of rows the session may not read. `upsert` cannot stage two hook chains against one atomic database decision; the honest version is a transaction the caller writes.
- **Session-relative value is a guarantee the surface owes, not a capability inherited from the ORM** — it is a leak-prevention rule in the same family as silent failure. Prisma 8 honours it natively: a relation reducer can be filtered first (`include('posts', (posts) => posts.where(...).count())`), and `combine()` holds several independently-scoped counts, each compiling to its own correlated subquery.
- **A terminal's result matches the caller's `.select()` exactly.** The engine widens the selection for what it needs — the `needs` closure of ADR-0025, and field-access resolution — then strips the additions before returning, mirroring what Prisma already does internally for join columns (`augmentSelectionForJoinColumns` returns `{ selectedForQuery, hiddenColumns }`).
- **Denial returns the empty value of the terminal's type:** `[]` from `all`, `null` from `first`, `null` from `update`/`delete`/`create`, and **`0` from a count**. Zero is the strongest answer available for an aggregate — indistinguishable from a genuine empty scoped set, which is precisely the property silent failure exists to provide.
- **Amended by [ADR-0045](0045-vector-search-is-an-engine-owned-terminal-over-a-native-vector-column.md): `nearest()` joins the read subset**, a core-owned terminal running a vector similarity search over a native `Vector(n)` column. It qualifies under the principle above — the engine scopes it exactly as it scopes any other read — and it is core-owned rather than plugin-registered, so the subset stays curated. It carries the one exception to the exactness rule below: it returns `{ item, score }` rather than a row, so the rule holds of `item` and the score sits beside it instead of becoming a field the list does not have.
- **Amended by [ADR-0047](0047-a-row-lock-is-an-engine-owned-two-statement-terminal.md): `forUpdate()` joins the read subset as a builder modifier**, reachable only on a transaction-bound builder. It passes the inclusion principle above on a stronger footing than a lock clause would have: Prisma 8 can emit no locking clause at all, so the terminal issues two statements — the ordinary scoped read, then an engine-written raw lock over exactly the primary keys that read returned. The locked set is therefore provably a subset of the readable set. `first()` and `all()` carry it; `aggregate` and `nearest()` cannot, having no keys to lock.
- **`context.db` keys by PascalCase list name** — `context.db.AuthUser`, not `context.db.authUser`. `getDbKey()` is deleted; `getUrlKey()` stays.
- **The secured surface is parameterised by the generated `Contract` type.** `PrismaClientLike = any` and the `any`-guarded conditional in `AccessControlledDB` are deleted rather than narrowed, and no `any` survives in the external type. What `contract.d.ts` declares, and how the generator emits it, is [#1039](https://github.com/OpenSaasAU/stack/issues/1039)'s.

## Considered Options

- **A `Collection` subclass** (`orm({ collections })`). Cheapest — the whole DSL is inherited free. Rejected on the reachability findings above. Two further notes from the same investigation: the subclass requirement is enforced only at _runtime_ (`AnyCollectionClass` is typed `new (...args: never[]) => object`, so TypeScript accepts any class and a non-`Collection` throws `ORM.ARGUMENT_INVALID`), and the one way found to make a base terminal unreachable — declaring an instance field `aggregate: never` — is a language artifact with no test or doc behind it, not a supported feature.
- **A naked `Collection` plus an engine-owned terminal function**, `await context.read(q)`. Zero surface to maintain and total DSL fidelity, but the secure path becomes a convention the caller must remember, and `q.all()` is shorter to type than the correct thing. Rejected for inverting the ergonomics.
- **Mirroring the full DSL** rather than a curated subset. Rejected: it commits the engine to chasing Prisma's surface forever, and it forces a scoping answer for methods where we do not have one — at which point the honest omission becomes a dishonest passthrough.
- **Preserving `.all()`'s dual streaming mode** by returning our own `AsyncIterableResult` that applies field visibility per row. Rejected for now; see the consequence below, and [ADR-0046](0046-a-secured-read-materialises-and-does-not-stream.md) for the settled rejection.
- **Amending ADR-0039 rather than adding this record.** Rejected: 0039 was decided by a different question at a different time, and it names its own gaps. A record that flags what it left open reads better closed by a successor than silently rewritten.

## Consequences

- **Terminals materialise; streaming is not available through the secured surface.** `.all()` returns a `Promise<T[]>`, not Prisma's dual-mode `AsyncIterableResult`. This was taken here to avoid pre-empting another decision: [#1046](https://github.com/OpenSaasAU/stack/issues/1046) owned whether the two-phase read survives, and committing the terminal to a streaming shape would have settled it from the wrong ticket. **Amended by [ADR-0046](0046-a-secured-read-materialises-and-does-not-stream.md), which revisited it on the merits once #1046 landed and confirmed the outcome on different grounds** — partial delivery defeats atomic denial, a re-entrant `resolveOutput` read deadlocks against `prisma dev`'s single connection, and the include path materialises parents anyway. The reason given here originally — that a denied stream has no natural `[]` — **does not hold**: an immediately-exhausted iterator satisfies silent failure exactly as `[]` does. Read 0046 for the standing argument.
- **`relationship-count.ts` (303 lines) and its `{ id: { in } }` marker machinery become a deletion**, the same shape ADR-0039 predicted for bare read and one hop: the semantic survives, the implementation goes. Note the new failure mode it inherits — `count()` _throws_ `RUNTIME.DECODE_FAILED` outside ±(2^53 − 1) rather than rounding, and that fires on the include path too.
- **The fragment API is deleted** — `defineFragment`, `runQuery`, `runQueryOne`, `ResultOf`, `buildInclude`, `pickFields`. [ADR-0005](0005-no-graphql-layer-migrate-via-fragments.md)'s fragment bullet is superseded; its no-GraphQL decision stands. Consumers to rework: `relationship-options.ts`, the filter engine's fragment-ANDing, and the migration guide. The `opensaas-migration` plugin skills also reference it, but the Keystone migration story is out of scope on this map.
- **`.select()` replaces rather than accumulates** in Prisma 8, and selection is exact — a bare read carries FK scalars, a selected read adds no implicit PK or FK. The wrapper preserves both behaviours; the widen-and-strip decision above is what keeps that promise while the engine still gets its dependencies.
- **PascalCase keys break every `context.db` call site**, on top of the break ADR-0039 already accepted. Paid once. It collapses three spellings of a list name to two.
- **ADR-0038 carried a false premise and is amended in place.** Raw SQL is not observable to `beforeCompile` either — raw plans arrive already lowered and bypass the hook entirely — so the tripwire cannot refuse a raw query, only ORM queries the engine did not build. The hybrid decision is unchanged (the extension seat loses the same capability), but this strengthens the case for renaming `context.prisma` to state its bypass.
- **The engine stamp's `beforeCompile` read path is structurally supported but not empirically demonstrated.** The types and wiring carry it (`plan.meta.annotations` is populated at plan-build time, before the runtime calls the middleware chain), but no shipped Prisma middleware or test reads an annotation inside `beforeCompile` specifically — the canonical consumer reads in `beforeQuery`. Verify before relying on it.
- **Everything here was reasoned against `8.0.0-rc.8`** (`prisma/orm@ca8fe14`). Two naming details already disagree between Prisma's docs and its source — `limit`/`offset` versus `take`/`skip`, and whether a schema namespace segment is required on the model accessor — so the method list above should be re-checked at GA.
