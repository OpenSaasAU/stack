# An opt-in Node build makes the Generated bundle loadable without a bundler

ADR-0008 made the **Generated bundle** loadable by the host's bundler — TypeScript with explicit `.ts` import extensions, statically imported so `next build` traces it — and explicitly **deferred** a pre-compiled JS entry "taken only if such a target becomes a real requirement." That requirement has arrived. A live module (better-auth's Prisma adapter, wired in the host's `auth-server.ts`) is imported by the Next server (bundled — fine) **and** by plain-Node consumers of the same file: Playwright e2e helpers that create a user through better-auth, and some server runtime paths. The `.ts` bundle cannot execute in plain Node (`Cannot use import statement outside a module` / extensionless sub-imports don't resolve), so pointing better-auth at the stack client regresses every plain-Node flow. We add an **opt-in Node build**: a compiled, plain-Node-loadable form of the bundle emitted alongside the default bundler form.

## Decisions

- **Opt-in and additive; the default is unchanged.** `output: { buildTarget: 'node' }` in `opensaas.config.ts` additionally emits a compiled form; absent it, the generator behaves exactly as ADR-0008. The compiled form is **not** the default — making it default would add a compile step to every `generate` and risk eagerly dragging the app's whole dependency surface into routes that only need the `.ts` form, which are the reasons ADR-0008 deferred it. `output` is a block (room for future keys) and `buildTarget` a string-literal union (room for future targets), but `'node'` is the only target today.
- **A deterministic compiled-JS form, not Node's native type-stripping.** The sanctioned form is compiled ESM (`.js` + `.d.ts`, with a `{"type":"module"}` marker) emitted to `.opensaas/dist/`. We rejected leaning on Node's `--experimental-strip-types`/`--experimental-transform-types`: it is version-gated and chokes on the `enum`/`namespace` constructs Prisma's generated client emits — too fragile to bless for a production auth path that must work on whatever Node the host runs.
- **The portable module imports the compiled entry explicitly; no conditional resolution.** A module that must run in both runtimes (`auth-server.ts`) imports the compiled entry directly (`.opensaas/dist/context.js`). Compiled ESM is valid JavaScript, so the bundler traces it *and* plain Node executes it — one specifier, both runtimes. We rejected a subpath-`imports`/`exports` condition map switching `.ts`↔`.js` per runtime: that is exactly the resolver magic ADR-0008 chose explicit extensions to avoid, its condition handling varies across webpack/Turbopack/Vite, and it lives in the host `package.json` the generator cannot safely own.
- **`tsc` does the compile; no new build dependency.** The bundle now type-checks clean (the point of #559/#560), so emitting with `tsc` reuses that guarantee, and TypeScript is already a dependency. `rewriteRelativeImportExtensions` turns the bundle's `.ts`-extension imports into runnable `.js` specifiers; `skipLibCheck` and `noEmitOnError: false` keep third-party `.d.ts` noise from blocking emit. esbuild/tsup would be faster but add a dependency and a separate `.d.ts` step for no gain on an opt-in path.
- **A real plain-Node consumer anchors it.** The feature is verified by an in-repo consumer that creates a user through better-auth while importing the compiled bundle under plain Node — not a bundler, not `tsx`. A generator output with no consumer in the repo cannot be verified and would rot.

## Why this is worth recording

A future reader will find `.opensaas/dist/` next to ADR-0008's "the bundle is bundler-loadable, a pre-compiled JS entry is deferred" and wonder which is true. Both are: ADR-0008's `.ts` bundler form remains the standing default, and this ADR adds an opt-in compiled target for the bundler-less consumer ADR-0008 anticipated. Reversing either side of this — making the compiled form the default, or replacing the explicit compiled-entry import with a conditional resolver — would reintroduce the dependency-surface and file-tracing costs ADR-0008 pinned down, or the cross-bundler resolution fragility this ADR rejected, so the split is worth recording.
