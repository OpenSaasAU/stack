# The row-lock statement is composed by the engine over the ORM's raw lane

Status: accepted

[ADR-0047](0047-a-row-lock-is-an-engine-owned-two-statement-terminal.md) made the row lock a two-statement terminal — a scoped ORM read, then an engine-written raw `SELECT … FOR UPDATE` over the primary keys it returned — because Prisma 8 can emit no locking clause anywhere. [#1073](https://github.com/OpenSaasAU/stack/issues/1073) re-confirmed the absence from the shipped AST and asked what that does to the record: who spells the statement, who owns its dialect, whether it is stamped, and whether the shape should wait on a later release. [ADR-0059](0059-the-engine-stamp-is-an-ambient-origin-the-executing-surface-enters.md) has since answered the stamping half — the statement is covered by the terminal's origin scope like every other statement the engine issues.

This record answers the rest. **`.forUpdate()` stays as the stack's spelling; the terminal composes the lock statement through Prisma's raw lane, not around it; and the dialect is split rather than moved.** Prisma owns identifier quoting, parameter placeholders, codecs and the executor. The stack owns the clause text — `FOR UPDATE`, `ORDER BY`, `LIMIT`, `IN` — and nothing else. The two-statement shape stands, and nothing waits on a post-`rc.8` release.

## What was measured

[The spike](../../specs/prisma-8/spikes/1077-row-lock/README.md), at `8.0.0-rc.8`, against a real PostgreSQL 14 for contention and PGlite for the default dev loop:

- **The raw lane carries everything the statement needs except its clause.** `quoteIdentifier`/`qualifyName` (`@prisma/orm-postgres/target/sql-utils`) quote identifiers properly (`we"ird` → `"we""ird"`); `codecRefForStorageColumn` reads the identity column's codec off the contract's storage, the same place the ORM's own `update()` reads it; `param(value, { codecId })` binds a key with that codec, so a `uuid` key renders `$1::uuid` and a text key `$1`; and the contract-bound tag `db.raw.sql` can be **invoked as a function** over strings the engine assembles — `db.raw.sql(strings, ...params)` — yielding a `lane: 'raw'` plan that `tx.query(plan)` executes on the transaction's connection. Rendered: `SELECT "id" FROM "public"."Post" WHERE "id" IN ($1, $2) ORDER BY "id" LIMIT $3 FOR UPDATE`, params `['p1', 'p2', 2]`.
- **A typed `db.sql` query cannot be spliced into the raw tag.** `templateParts` treats any interpolation carrying both `buildAst` and `build` as a raw row query and spreads `.buildAst().parts`; a DSL `SelectQuery` has both methods and a `SelectAst` has no `parts`, so it throws. The shape in which Prisma renders everything but the two words `FOR UPDATE` is not available.
- **It is a lock, on both targets.** `EXPLAIN` shows `LockRows → Sort → Bitmap Heap Scan` and `pg_locks` shows `RowShareLock` on the table inside the transaction, on PGlite as on Postgres 14.
- **It behaves as ADR-0047 says under contention** (Postgres 14, second connection via `pg`): a `FOR UPDATE NOWAIT` on a locked key fails `55P03` and on an unlocked key succeeds; after commit the key is acquirable; a row deleted between the scoped read and the lock is absent from the locked set (`[p1, p2]` read, `[p1]` locked); `SKIP LOCKED` returns only the unheld keys.
- **Prisma's raw guardrails are opt-in middleware, and the statement passes them.** The client installs none; `lints()` and `budgets()` (`@prisma/orm-postgres/family-runtime`) are what an application would add. Mutation classification is prefix-anchored, so `FOR UPDATE` never reads as a mutation. With `LIMIT` present the statement passes `lints()` at every severity and `budgets()`; without it, only `lints({ severities: { noLimit: 'error' } })` refuses it.
- **Nothing newer than `rc.8` changes any of this.** `@prisma/orm-family-sql@8.0.0-rc.8-dev.12`, the `dev` dist-tag published the day this was written, carries the identical `AnyQueryAst` and no lock string; `latest` is still `rc.8`.

## Decision

- **`.forUpdate()` is the stack's spelling, and the record says so.** ADR-0047 already lowered the lock to raw text; it now states plainly that the builder modifier is ours, that Prisma provides no lock method, and that the terminal composes the statement. The surface, the transaction-only rule, `first()`/`all()` carrying the modifier, the identity-row rule, the vanished-row rule, deterministic `ORDER BY <pk>` and the advisory seat are unchanged.
- **The statement is composed through the raw lane.** The terminal reads the table name and the single primary-key column from the contract's storage, quotes them with the target package's helpers, binds each key with `param()` and the identity column's own codec, and invokes the contract-bound raw tag over those parts. The plan runs through `tx.query(plan)` inside the terminal's engine origin, and the terminal reads the keys back to compute the locked subset. No driver call, no string-concatenated value, no second quoting routine.
- **`IN ($1 … $n)`, one parameter per key, with `LIMIT $n+1`.** Per-key binding works for every identity codec the contract can name; the `= ANY($1)` form needs an array codec per key type and `rc.8` ships only `text[]`. The `LIMIT` is the key count: it is true by construction and satisfies the one guardrail an application can arm against an unbounded raw `SELECT`.
- **The dialect is split, not moved.** Under the one-provider decision ([ADR-0003](0003-deployment-uses-postgres-and-prisma-migrate.md), [#1040](https://github.com/OpenSaasAU/stack/issues/1040)) there is one dialect, and Prisma renders every identifier, placeholder and cast in it. What the stack authors is the locking clause and its ordering and bound, which is precisely the part no target-agnostic layer could write. A second provider, if one ever came, would give this terminal a target-keyed clause renderer — one string per target — not a rewrite.
- **`advisoryLock(key)` is spelled the same way:** `SELECT pg_advisory_xact_lock(hashtext($1))` through the raw tag, run with `tx.execute()` since it returns nothing.
- **The two-statement shape stands, and nothing waits.** ADR-0047's one-statement alternative required the filter-to-SQL translator ADR-0045 deleted; the ORM cannot carry the clause; and the shipped line through today's `dev` build shows no sign of one. ADR-0047's GA re-verification item is the right place for that fact to change, and if it does the collapse is still additive.
- **`NOWAIT` and `SKIP LOCKED` stay out**, now on a measurement rather than an assumption: both are free at the SQL level, and ADR-0047's reasons for excluding them — a second meaning for Silent failure, a failure mode outside ADR-0042's set — are untouched.

## Considered options

- **Splice a typed `db.sql` select into the raw tag and append `FOR UPDATE`.** The best division of labour — Prisma renders the query, the stack adds two words. Foreclosed at `rc.8` by the raw tag's interpolation check; recorded as a re-verification item, since a fix upstream would let the terminal shed its quoting call.
- **Hand-write the SQL and run it on the `pg` driver.** Rejected: it leaves the raw lane's codecs, the transaction's connection and the tripwire behind, and ADR-0059 covers the statement only because it executes through the client.
- **`= ANY($1::<type>[])`, one array parameter.** Rejected for now: it needs an array codec per identity type and only `text[]` ships; per-key binding costs nothing and generalises.
- **Bare interpolation, letting Prisma infer `pg/text` and Postgres coerce.** Works on a uuid column today because the text codec adds no cast, but it is the ORM's identity codec that should decide, not a coincidence of coercion.
- **Omit the `LIMIT`.** Rejected: the bound is free and is the one thing an armed `lints()` would refuse.
- **Reopen the two-statement shape** — a single scoped lock, or waiting for a lock clause. Rejected above.

## Consequences

- **ADR-0047 is amended in place**, not superseded: its decision holds, and this record supplies the spelling and ownership it left open.
- **The escape-only test narrows to contention.** The statement parses, plans as `LockRows` and takes `RowShareLock` on PGlite, so the terminal's spelling — the rendered SQL under the recording middleware, the codec on each bound key, the vanished-row subset — is an ordinary [ADR-0057](0057-engine-tests-run-against-an-in-process-postgres-through-the-clients-construction-options.md) test on the default harness. Only `NOWAIT`-style contention needs the `DATABASE_URL` escape, which is what `CONTEXT.md`'s Escape-only test entry already says.
- **ADR-0056's re-verification note is corrected.** Prisma's raw guardrails do not "regex-refuse DDL by default": they are opt-in `lints()`/`budgets()` middleware, and the DDL prefix regex only classifies a statement for the read-only-intent lint. The ported `CREATE EXTENSION` script meets nothing unless an application installs them.
- **A table without a single-column primary key cannot be locked**, matching the ORM's own `ORM.ROW_IDENTITY_MISSING` on `update()`; composite keys are out of this map's scope ([#1047](https://github.com/OpenSaasAU/stack/issues/1047)).
- **Two re-verification items at GA**, both additive: whether the raw tag accepts a typed query interpolation (collapsing the quoting call), and whether `adapter/column-types` grows a `uuidColumn` (ADR-0048's `uuid(7)` ids need one; `pgUuidColumn` in `target` is the `rc.8` route).
- **Everything here was measured at `8.0.0-rc.8`** on PostgreSQL 14.20 and PGlite 0.5.8, from a programmatic contract.
