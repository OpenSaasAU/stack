# The engine stamp is an ambient origin the executing surface enters, not a per-plan annotation

Status: accepted

[ADR-0049](0049-extension-packs-are-declared-the-tripwire-is-stack-owned.md) made the Engine stamp a Prisma **annotation** written through each terminal's `configure` callback, and [ADR-0038](0038-access-enforcement-stays-in-terminal-operations-with-the-spi-as-a-tripwire.md)'s tripwire a `beforeCompile` that throws on any plan without one. [#1073](https://github.com/OpenSaasAU/stack/issues/1073) measured that design against `8.0.0-rc.8` and found it unshippable: an annotation attaches to **one compiled plan per terminal**, and every further statement a terminal issues — the identity `SELECT` before `update()` and `delete()`, the whole of a nested write, root `INSERT` included — is built from `emptyState()`, from which the caller's annotation map is unreachable. The tripwire as specified would refuse the secured surface it protects (`update()` 1/2, nested writes 0/3), and the middleware context carries **no discriminator** — no parent id, no logical-call id, no statement index — with which to teach it the difference.

**This record changes what the mark is, not what the tripwire does.** The Engine stamp becomes an **ambient origin**: an `AsyncLocalStorage` store that the executing surface enters around exactly the execution it performs, and that the tripwire reads in `beforeCompile`. A statement's origin is then a property of the async context it was issued in, which every statement of a logical call shares, rather than a property of the plan object, which only one of them carried. The per-plan annotation is retired; the tripwire still throws on absence, everywhere, and the store holds nothing but `'engine' | 'unsafe'`.

## What was measured

[The spike](../../specs/prisma-8/spikes/1076-ambient-origin/README.md), on ADR-0057's PGlite harness at `8.0.0-rc.8`, with a `beforeCompile` reading the store and the scope entered around the ORM call with the `await` inside it:

| shape                                                                                       | statements | origin visible                       |
| ------------------------------------------------------------------------------------------- | ---------- | ------------------------------------ |
| `all()`, `include().all()`, `first()`, `aggregate()`, `create()`, `updateAll()`, `upsert()` | 1          | **1/1**                              |
| `update()`, `delete()`, `deleteAll()` + include                                             | 2          | **2/2**                              |
| nested `create`, nested `connect`                                                           | 3          | **3/3**                              |
| two terminals inside one `db.transaction()`                                                 | 3          | **3/3**, each tagged by its own call |
| `dsl` plan via `runtime().query()`, `raw` plan via `runtime().execute()`                    | 1          | **1/1**                              |

Sixty concurrent `update()` calls (120 statements) alternating engine-scoped, unsafe-scoped and foreign, over a saturated pool of ten: every scoped call saw exactly its own tag on both statements and all forty foreign statements saw none. A foreign query throws. A value built _inside_ a scope and executed _outside_ it throws. A value built outside and executed inside is covered. A query issued from `als.exit()` inside a scoped terminal is refused. A refusal on the second statement of `update()` rolled back its implicit transaction and left the client usable, and the error reached the caller unwrapped. `als.run` costs 0.145 µs; around a warm `first()` it is within noise. `prepare()` ran `beforeCompile` once, at prepare, and **zero** times per execution, executing unrefused with the tripwire in throw mode.

## Decisions

- **The Engine stamp is ambient.** Core owns one module exporting the store, the tripwire and the refusal error. A surface that executes a query enters the store around that execution; the tripwire reads it and throws when it is absent. The store's value is `'engine' | 'unsafe'` and nothing else — no session, no list key, no operation. ADR-0038's two properties survive verbatim: the tripwire carries no policy and no session, and only an absent mark is rejected.

- **One mechanism, not two.** Terminals stop calling `.annotate()`; the Unsafe surface's executors stop copying plans to attach a stamp; ADR-0057's recording middleware asserts the stamp's presence by reading the same store from inside its own `beforeCompile`. Keeping the annotation as observability beside the store was rejected: two interpreters of one signal is the drift ADR-0030, ADR-0031, ADR-0044 and ADR-0055 each spent a record eliminating, and a plan found without an annotation could no longer be told apart from a bug.

- **The scope wraps the ORM call, never the operation.** A terminal enters the store around exactly the ORM call it issues, with the `await` inside, and around nothing else. Hooks — `resolveInput`, `validate`, `beforeOperation`, `afterOperation`, `resolveOutput` — therefore run outside it by construction, so a hook's own read has to reach the secured context or the Unsafe surface, each of which marks itself. This keeps ADR-0049's "who may stamp reduces to who may reach that surface" literal: a hook running inside the engine's scope would be silently blessed. Core's helper takes an async function and awaits it inside the scope, because the four terminals that return Prisma's `AsyncIterableResult` (`all()`, `updateAll()`, `deleteAll()`, `runtime().query()`) execute at the first `then`/`next` rather than at the call, and a helper that returned the lazy value would let the scope close before the query ran — a refusal, not a leak, but a wrong one.

- **The Unsafe surface's ORM lane is a transparent Proxy.** [ADR-0056](0056-app-authored-sql-lives-on-the-unsafe-surface-which-stamps-at-execution.md) left it to this record because ORM terminals execute themselves. A `Proxy` over Prisma's `orm` runs every method call inside the unsafe scope, re-proxies a returned `Collection`, and re-enters the scope on `then`/`next` of a lazy result. Measured covering `update()` 2/2, nested create 3/3, a chain whose terminal is called later outside any scope, an `include` refinement, streaming, `first()` and `aggregate()`. It is not the "mirror the full DSL" ADR-0041 rejected — a Proxy chases no method list — and it extends ADR-0056's "does not hand out the bare client" to the ORM lane. Better-auth's adapter reaches it through the same surface and is marked by construction.

- **`prepare()` and `runtime()` stay unexposed on both surfaces, now on a measured fact.** A prepared statement executes with no `beforeCompile` at all, so exposing `prepare` would be a fail-open route through a surface that promises the opposite. `runtime()` stays out because an already-compiled `ExecutionPlan` handed to it bypasses the middleware chain (#1073's correction of #1038). `RuntimeCore.runBeforeCompile` being dead on the live path stops mattering once nothing reaches `prepare`.

- **ADR-0022's fail-closed guarantee at this seam, said out loud.** The tripwire throws in every environment on every plan reaching `beforeCompile` with no origin. No warn mode and no dev-only mode — ADR-0038 rejected both, and nothing measured here reopens them. A refusal inside an implicit transaction rolls it back. The error is a stack-owned type in ADR-0042's family, reaching the caller unwrapped.

- **ADR-0038's rejection of ALS stands.** That rejection concerned carrying a **session** set by a **caller**: binding at execution meant a query value that outlived its scope ran unscoped, on an idiom that looked correct. Here the executor enters the store around its own execution, so no application idiom touches it, and if a stack bug did let a value escape the result is a throw. It is the inversion ADR-0049 recorded for annotations, applied to scopes: per-scope is exactly right when absence is refusal. Scoping a query to a session remains a rebind, and ADR-0012 is untouched.

## Considered options

- **Narrow what the tripwire throws on by AST shape** — treat a PK-projecting, `LIMIT 1`, PK-equality `SELECT` as an engine follow-up. Rejected: that is also the exact shape of a probing query, so the exemption is fail-open in precisely the direction ADR-0022 forbids, and it still sees nothing of a nested write, whose root `INSERT` is unstamped too.
- **Stack-built plans throughout** — build every statement via the DSL or raw lane and stamp each, since per-plan stamping works when the stack owns the plan. Rejected: it discards the ORM lane wholesale — typed filter merging (#1031), native include refinement (ADR-0044, #1063), the `Collection` the wrapper is opaque over (ADR-0041) — to recover a backstop ADR-0038 chose _because_ it was nearly free. Two statements the engine builds itself, such as ADR-0047's lock, are still stamped under this record, by the scope rather than by copying.
- **Downgrade to a warning, or throw only in development and test.** Rejected, again: ADR-0038's options already refused it, and the measurements remove the pressure that made it tempting.
- **Keep the annotation beside the store.** Rejected above.
- **Hand out Prisma's bare `orm` on the Unsafe surface and teach the tripwire a lane exemption.** Rejected: the fail-open shape ADR-0056 refused from the SQL side.
- **A scope function, `unsafe.run(orm => …)`, instead of a Proxy.** Sound — a value that escapes the scope is refused — but it is the ergonomic trap ADR-0038 described, now on a surface whose users are the ones most likely to hold a query value across an `await`.
- **Wait for Prisma to propagate annotations into follow-up statements.** The typings' "do not currently flow" suggests intent. Rejected as a dependency: a security backstop resting on a pre-release API's roadmap is what ADR-0038 refused, and the ambient route depends on less of the SPI than the annotation did — only that `beforeCompile` exists and runs in the caller's async context, against `defineAnnotation`, `handle.read`, `PlanMeta.annotations` and per-plan propagation, the last of which is what broke.

## Consequences

- **ADR-0049 is amended in place.** Its stamp is an ambient origin; its "fail-open objection inverts" paragraph holds with its object changed; its deletability bullet holds — store, tripwire and error are one exported module, and a terminal loses a scope entry instead of an `annotate()` call. Its `handle.read(plan)` re-verification item on #1070 is moot rather than answered.
- **ADR-0038 is corrected twice and amended once.** Raw plans _do_ reach `beforeCompile` (`lane: 'raw'`), so its #1038 correction was itself wrong: what bypasses is an already-compiled `ExecutionPlan`, reachable only through `runtime()` and `prepare()`, which neither surface exposes. Its "unobservable" consequence goes the same way; "unfilterable" stands. And its ALS paragraph gains the note above.
- **ADR-0050 keeps its decision and loses its primary argument.** It removed nested relation input partly because a nested write's statements arrive unstamped and the tripwire refuses them. Under an ambient origin they would be covered (3/3), so that foreclosure is retired. The decision stands on the grounds the record already carried: Prisma issues the related rows itself, so the engine cannot run the Write Pipeline — access, hooks, validation — per nested row without ADR-0010's rejected decomposition; a nested write stages _N_ hook chains against one atomic decision, the reason `upsert` was excluded; six of nine kinds have no ORM construct; and no first-party consumer exists. Its `connect` line is corrected too: three statements at the database, not two, all covered.
- **ADR-0056's executors enter the scope rather than copy the plan.** "The executor is the audited act" survives; the copy-and-stamp mechanism does not. Its ORM lane is resolved as the Proxy above, and its "does not hand out the bare client" now covers `orm`.
- **ADR-0047's one wrong consequence is corrected.** The engine's raw lock statement is observable to the tripwire and covered by the `forUpdate()` terminal's scope. Its spelling stays with [#1077](https://github.com/OpenSaasAU/stack/issues/1077), which this closes the way for.
- **`CONTEXT.md`'s Engine stamp and Unsafe surface entries are rewritten.** No new term: the guarantee keeps its name; only its mechanism changed.
- **The bundle already meets the runtime requirement.** `AsyncLocalStorage` is stable in every Node line ADR-0054 supports, and the bundle is a Node target.
- **The consumer sweep widens.** Terminals lose `.annotate()`; core gains the origin module (store, helper, tripwire, error) that the generator and ADR-0057's `createTestContext` both install; the Unsafe surface's `orm` becomes the Proxy and its `query()`/`execute()` enter the scope; the recording middleware reads the store.
- **One re-verification item at GA**, the opposite of the one retired: that `beforeCompile` keeps running in the caller's async context. ADR-0057's suite runs the whole engine under the tripwire, so a Prisma change that dropped async context fails the suite rather than a login in production. If Prisma ever propagates annotations into follow-ups, nothing here changes.
- **Numbered 0059.** 0057 merged to `main` while this was written and 0058 was taken on an open branch.
- **Everything here was measured at `8.0.0-rc.8` on PGlite**, whose serialised transactions make the interleaving result a statement about async-context isolation, not database concurrency — which is the property it was measuring.
