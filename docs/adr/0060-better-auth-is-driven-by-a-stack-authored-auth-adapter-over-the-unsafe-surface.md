# Better-auth is driven by a stack-authored Auth adapter over the Unsafe surface

Status: accepted

> **Amended 2026-09-07 by [The Auth adapter over the Unsafe surface](https://github.com/OpenSaasAU/stack/pull/1221)** ([#1161](https://github.com/OpenSaasAU/stack/issues/1161), review of the implementation). The `consumeOne` decision below is unchanged — it is still `where(…).delete()` on the ORM lane — but the mechanism sentence attached to it is wrong. Prisma does **not** lower that to one `DELETE … RETURNING`: it emits a SELECT that resolves the identity and then a DELETE, so two racing consumers can both resolve the same row and both be answered it. The at-most-one guarantee therefore comes from the shape better-auth's own reference adapter uses, and that is what is implemented: the pair runs inside one transaction on the Unsafe surface's transaction-bound lanes, and the row is handed back only when the DELETE itself claimed it (a row-count gate). Read the sentence below as "two statements under a transaction, gated on the delete's own count", not as a single returning statement.
>
> **Amended 2026-09-05 by [Delete the Node build, enforce erasable-only output, and retire the scaffolder's `--db` flag](https://github.com/OpenSaasAU/stack/issues/1138)** (Prisma 8 map). The last decision below — "The plain-Node anchor keeps its shape" — rests on a file that no longer exists. `examples/starter-auth/scripts/node-build-create-user.mjs` and `e2e/starter-auth/04-node-build.spec.ts` were **deleted**, not re-targeted: the examples do not build until the spec's example conversion, and there is no Prisma 8 better-auth adapter to drive them with until this record is implemented. The property [ADR-0054](0054-the-generated-bundle-loads-natively-under-plain-node-from-the-committed-contract.md) actually asserts — the generated bundle loads under the real `node` binary with no flags, no loader and no bundler — is guarded instead by `packages/cli/tests/bundle-node-load.test.ts`, at CLI level over the contract fixture. What that test does **not** cover is better-auth: no `createAuth`, no `signUpEmail`, no Auth adapter. So this record's verification plan is short one item, and implementing it should bring a better-auth-shaped anchor back with the example conversion — tracked on [#1178](https://github.com/OpenSaasAU/stack/issues/1178).

`@opensaas/stack-auth` wires better-auth through `prismaAdapter(context.prisma, { provider })` (`packages/auth/src/server/index.ts`), behind the lazy `Proxy` [ADR-0014](0014-orm-client-access-stays-async-document-the-sync-escape-hatch.md) documents. That adapter is written against Prisma Client's per-model delegates — `findFirst`/`findMany`/`update`/`updateMany`/`delete`/`deleteMany`/`count`/`$transaction`, `WhereUniqueInput` flattening, `P2025` for not-found — none of which a Prisma 8 client has: the client is `postgres({ contractJson })`, its ORM lane is `Collection`s, and a query is a value ([ADR-0039](0039-context-db-is-a-query-value-surface-with-engine-owned-terminals.md)). better-auth 1.7.1 ships adapters for prisma, drizzle, kysely, mongodb and memory only; its `main` (1.7.2) still peers `@prisma/client ^5 || ^6 || ^7`; and the sole upstream trace of Prisma 8 is [better-auth#11077](https://github.com/better-auth/better-auth/issues/11077) (2026-08-31), an unanswered feature request that targets the Prisma-Client-shaped migration, not `@prisma/orm-postgres`. Two standing records had already assumed an answer without naming one: [ADR-0038](0038-access-enforcement-stays-in-terminal-operations-with-the-spi-as-a-tripwire.md) keeps the Unsafe surface partly so that "the auth adapter needs no exemption machinery", and [ADR-0049](0049-extension-packs-are-declared-the-tripwire-is-stack-owned.md) says better-auth's adapter gets the unscoped mark "by construction, being handed that surface through `rawOpensaasContext`". [#1086](https://github.com/OpenSaasAU/stack/issues/1086) asked what that adapter is.

**The auth plugin hands better-auth an Auth adapter the stack authors**, built with better-auth's `createAdapterFactory` and driving the Unsafe surface: its ORM lane for every operation a `Collection` can express, its typed SQL lane for the two it cannot. Auth writes share the singleton connection, run inside the ORM's transaction model, and are marked as intentionally unscoped the way ADR-0049 assumed. Waiting on upstream is rejected because there is nothing to wait on; better-auth's Kysely adapter over the shared `pg.Pool` is rejected because it is the separate client instance ADR-0049 already refused by name.

## What the adapter has to be

Read at better-auth `1.7.1` (`packages/core/src/db/adapter/{index,types,factory}.ts`):

- **Ten methods, all mandatory:** `create`, `findOne`, `findMany`, `update`, `updateMany`, `delete`, `deleteMany`, `count`, and — new since the version the repo's docs describe — `consumeOne` (single-use credential consume, at most one row) and `incrementOne` (atomic guarded counter). The factory throws at construction if either of the last two is missing. `createSchema` is optional.
- **Transactions are a factory config option, not a method.** Without one the factory runs the callback against the plain adapter with no atomicity (`createAsIsTransaction`). The reference adapters implement it by building a second factory instance bound to the transaction handle.
- **`where` is a flat list**: eleven operators (`eq ne lt lte gt gte in not_in contains starts_with ends_with`), an `AND`/`OR` connector per clause, a `mode: 'insensitive'` flag; plus `sortBy`, `limit`, `offset`, `select`.
- **Joins are opt-in** (`advanced.database.joins`, default off); the factory falls back to separate queries when an adapter ignores `join`.
- **The conformance harness is `@better-auth/test-utils@1.7.1`** (`testAdapter` plus the suites normal, uuid, numberId, caseInsensitive, joins, transactions, authFlow). `better-auth/adapters/test` was removed in 1.5.

Read at Prisma `8.0.0-rc.8` (`packages/3-extensions/sql-orm-client/src/{collection,types,filters}.ts`): the `Collection`'s operators are `eq neq gt lt gte lte like in notIn isNull isNotNull`, plus the Postgres target's `ilike`; `contains`/`starts_with`/`ends_with` are `like`/`ilike` patterns the caller escapes; `OR` needs the `or()` combinator, which Prisma's own skill documents as an import from an internal package today; `count` is `aggregate((a) => ({ n: a.count() }))`; `update()` and `delete()` return the row or `null`; there is no `SET n = n + δ` expression on the ORM lane, and `deleteAndCount` requires a prior `.where()`.

## Decisions

- **ORM lane primary; typed SQL for exactly the operations the `Collection` cannot express.** Eight methods are `Collection` calls on the Unsafe surface's ORM lane. `incrementOne` is one typed-SQL `UPDATE … SET n = n + δ … RETURNING`, and `deleteMany` with an empty `where` — which better-auth's own test cleanup issues — is one typed-SQL unconditional `DELETE`. Both run through the Unsafe surface's own executors and are marked as unscoped there ([ADR-0056](0056-app-authored-sql-lives-on-the-unsafe-surface-which-stamps-at-execution.md)). `consumeOne` is `where(…).delete()` — see the 2026-09-07 amendment at the top of this record for the mechanism that actually delivers its at-most-one guarantee: the resolve-then-delete pair runs in one transaction and the row is answered only when the delete claimed it. If the build finds the internal `or()` import unacceptable, the fallback is typed SQL throughout — still the Unsafe surface, never a second client.
- **The Unsafe surface carries the ORM lane — `Collection`s and `transaction` — and this record says so.** ADR-0056 named the SQL builder, the raw tag and the executors and left the ORM lane to [#1076](https://github.com/OpenSaasAU/stack/issues/1076); ADR-0049 assumed it. The Auth adapter is the lane's first concrete consumer, so its existence is recorded here. **How a query on that lane acquires its mark is not decided here.** At write-up, [ADR-0059](0059-the-engine-stamp-is-an-ambient-origin-the-executing-surface-enters.md) (#1076, on an open branch) resolves it as a transparent `Proxy` that enters the unsafe origin around each call, measured covering both statements of `update()` and `delete()`; this record depends on the lane existing and being marked, not on the mechanism, and the adapter's requirement — every statement of `update()`, `delete()` and `consumeOne` must pass the tripwire — is stated so any later change to the tripwire is checked against it.
- **The ORM mints auth ids.** The adapter sets `disableIdGeneration: true` (with `supportsUUIDs: true`, `supportsNumericIds: false`), and `authPlugin`'s per-list pin under [ADR-0048](0048-the-deleted-psl-constructs-become-config-defaults-not-ddl.md) is named: `uuid7`, the same strategy as every other list. `create()` returns the inserted row, so better-auth learns the id exactly as it did from Prisma Client. `advanced.database.generateId` joins the passthrough keys `buildBetterAuthOptions` refuses: an app-supplied generator would write a non-UUID into a uuid column.
- **`config.transaction` is implemented**, rebinding a second factory instance to the transaction-bound Unsafe surface ADR-0056 gives the transaction context — the shape better-auth's own Kysely and Prisma adapters use. Sign-up writes user, account and session; silently losing atomicity on the login path is the degradation [ADR-0022](0022-access-control-fails-closed-when-it-cannot-scope.md) exists to refuse. [ADR-0042](0042-transactions-lose-isolation-levels-and-database-errors-become-stack-owned.md)'s no-isolation-level rule applies unchanged: auth transactions run at Read Committed.
- **Joins are not implemented, and `advanced.database.joins: true` is refused** in the passthrough guard. The factory's fallback is correct but silent; a flag that appears to enable native joins while nothing changes is the lie the guard exists to catch. Recorded as a known limit of the adapter.
- **`createSchema` is not implemented.** Auth lists already derive from `getAuthTables` ([ADR-0033](0033-auth-lists-derive-from-better-auths-own-table-definitions.md), [ADR-0034](0034-plugin-tables-derive-through-the-same-registry-as-the-base-auth-models.md)) and the stack's generator emits the contract; a second emitter would be a second schema source. better-auth's CLI (`generate`, `migrate`) is unsupported against this adapter, and the adapter says so if asked.
- **Errors stay raw.** ADR-0042 excludes the Unsafe surface from normalisation and this record keeps it excluded: a raced unique violation surfaces as the driver's `SqlQueryError`, identical in effect to today's escaped `P2002`; better-auth checks existence before every create, so nothing else changes. No not-found mapping is needed — the `Collection`'s `update()`/`delete()` return `null` natively where the Prisma adapter had to translate `P2025`.
- **The adapter addresses lists, not tables.** better-auth's `getModelName`/`getFieldName` return the mapped table and column names, which is what a SQL adapter wants; a `Collection` is keyed by list key and field key. The derived Auth lists keep better-auth's default field key as the field name and carry the column map in `db.map` (`derive-auth-lists.ts`), and `deriveAuthLists` already builds the model → list-key registry, so the adapter resolves models through that registry and fields through better-auth's default names, and the contract applies the column map. `contains`/`starts_with`/`ends_with` and insensitive `eq` reuse the engine-owned LIKE escaping [ADR-0055](0055-the-secured-surface-accepts-a-where-vocabulary-the-engine-lowers.md) introduced, lowered to `like`/`ilike`; no second escaper.
- **It lives in `@opensaas/stack-auth`** (`packages/auth/src/adapter/`), used by `createAuth` and `buildBetterAuthOptions` internally; core contributes only the Unsafe surface type and the escaping helper. **`createAuth(config, rawOpensaasContext)` keeps its signature**: the `Proxy` defers method calls, not client construction (ADR-0014), so `getDatabaseConfig` builds the adapter from the resolved context's Unsafe surface where it called `prismaAdapter` before, and `betterAuthOptions.database` stays refused.
- **Conformance is better-auth's own suites**, run in `packages/auth` over the in-process Postgres [ADR-0057](0057-engine-tests-run-against-an-in-process-postgres-through-the-clients-construction-options.md) establishes: normal, uuid, caseInsensitive, transactions, authFlow. numberId is skipped (Auth lists are string-keyed) and joins is skipped (above). This is to the adapter what `auth-lists-drift.test.ts` is to the schema: upstream's definition of correct, run against our translation, so a better-auth release that adds another mandatory method fails a test rather than a login.
- **The plain-Node anchor keeps its shape.** ~~`examples/starter-auth/scripts/node-build-create-user.mjs` still calls `signUpEmail` through `createAuth` over `.opensaas/context.ts` ([ADR-0054](0054-the-generated-bundle-loads-natively-under-plain-node-from-the-committed-contract.md)'s re-target) and now proves that the Auth adapter creates a user through a Prisma 8 client under plain Node.~~ _Struck by [#1138](https://github.com/OpenSaasAU/stack/issues/1138): that script and its e2e spec were deleted rather than re-targeted, so there is no better-auth anchor to keep the shape of. See the amendment at the top of this record._

## Considered options

- **better-auth's Kysely adapter over the shared `pg.Pool`.** Real and cheap: `database: pool` is auto-detected (`"connect" in db`), turns transactions on, and `kysely` is already better-auth's hard dependency; Prisma 8 takes the same pool via `postgres({ contractJson, pg })`. Rejected because it is the separate client instance ADR-0049 refused — auth SQL outside every mark, on a query surface whose transactions are not the ORM's, invisible to the contract the migrations hash — and because `db.client.pg` is optional under ADR-0049, so the stack would have to own a pool unconditionally to have one to share.
- **Wait for upstream.** Nothing merged, open or announced beyond #11077, which targets the wrong client. A decision to wait blocks the spec's auth section on a date nobody owns.
- **Typed SQL throughout.** Viable — better-auth's contract is SQL-shaped and the executor's mark is already settled — and kept as the fallback. Not chosen first because the ORM lane is the surface ADR-0049's sentence is written about and the codec-typed field proxies catch a mis-addressed column at compile time.
- **better-auth mints ids** (a text id column with no default), or **mints UUIDv7 via `customIdGenerator`**. Rejected: the first makes Auth lists the one place ids are not `uuid7`; the second keeps two generators aligned for one id shape.
- **Implementing `createSchema`** so better-auth's CLI works. Rejected as a second schema source.
- **Normalising `23505` in the adapter.** Rejected: a third normalisation site, for a path better-auth cannot act on differently.
- **Changing `createAuth` to take the Unsafe surface directly.** Rejected: every app's `lib/auth.ts` and both documented recipes change for no capability.
- **Accepting the transaction fallback** or **implementing joins now.** Rejected above: the first is silent atomicity loss on the login path; the second is surface for a feature no auth flow in the repository turns on.

## Consequences

- **ADR-0038 and ADR-0049 stay literally true, and each gains its mechanism.** "The auth adapter needs no exemption machinery" now means the Auth adapter is handed the Unsafe surface. "By construction" now names the construction: the ORM lane for eight methods, the typed SQL lane through the surface's own executors for two. ADR-0014's context paragraph, ADR-0048's unnamed pin and ADR-0054's trailing note are amended in place. Nothing is superseded.
- **The consumer sweep widens:** `packages/auth/src/server/index.ts` drops `prismaAdapter` for the Auth adapter; `packages/auth/package.json` drops its `@prisma/client` peer and gains `@better-auth/test-utils` as a dev dependency; the passthrough guard gains `advanced.database.generateId` and `advanced.database.joins`; `authPlugin` pins `db.idField: 'uuid7'`; `packages/auth/CLAUDE.md` and root `CLAUDE.md`'s auth paragraphs stop naming `prismaAdapter`.
- **Known limits of the adapter, stated:** no native joins; no `createSchema`; `OR` rests on an internal Prisma import until the combinators reach the public façade; a single-row `delete()` on the ORM lane is two statements, not one `DELETE … RETURNING`.
- **`CONTEXT.md` gains Auth adapter.** The Unsafe surface entry's "better-auth's own flows run here by design" is unchanged in meaning; ADR-0059 is rewriting that entry concurrently and this record does not touch it.
- **Re-verification items.** better-auth's adapter contract grew two mandatory methods between 1.4 and 1.7; the conformance suites are what notice the next one. Prisma's `or()` import path and the `Collection`'s operator list were read at `8.0.0-rc.8` and join the map's GA gate.
- **Numbered 0060 provisionally**, per the map's numbering rule: 0058 was on `main` and 0059 on an open wayfinder branch at write-up time.
