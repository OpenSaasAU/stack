# Engine tests run against an in-process Postgres through the client's construction options, not a mocked delegate

Status: accepted

[ADR-0002](0002-testing-and-ci-strategy.md) gates the PR on the security-critical core paths, and every test behind that gate hands `getContext(config, prisma, session)` a hand-built object of `vi.fn()` per-model delegates. [ADR-0041](0041-the-secured-surface-is-an-opaque-wrapper-over-a-prisma-8-collection.md) made `context.db` an opaque wrapper whose terminals resolve access lazily, and [#1040](https://github.com/OpenSaasAU/stack/issues/1040) declined to say whether that mock survives it. This record answers: **it does not, and the wrapper's opacity is not the reason.** Prisma 8 has no per-model delegate to stand in for. A client is built once by `postgres({ contract | contractJson, url | pg, middleware, extensions })`, and every terminal runs through runtime, adapter and driver — so the only things a test can substitute are the construction options Prisma itself exposes. The injection point in `getContext` survives unchanged; what is injected changes from a fake of the model surface to a real client built with test-chosen options.

Everything below was measured against `8.0.0-rc.8` in [the spike](../../specs/prisma-8/spikes/1068-test-seams/README.md), which also carries the reproduction scripts and a **Known limits** block.

## What the spike established

| Question                                                                         | Result                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| In-process PGlite behind `@electric-sql/pglite-socket` drives Prisma 8's runtime | **Yes** — create, filtered read, update, `db.transaction()`, has-many include all correct; two instances coexist in one process                                                                                             |
| Cost                                                                             | ~420 ms per fresh schema'd instance (+250 ms WASM compile for the first in a process); 0.12 ms per warm `.where().all()`; `dbUpdate` for two tables 50 ms                                                                   |
| Schema from the programmatic contract                                            | **Yes** — `createPostgresControlClient(...).dbUpdate({ contract, mode: 'apply' })` creates tables and signs the marker; `schemaVerify` clean                                                                                |
| pgvector on PGlite                                                               | Queries **yes** (`CREATE EXTENSION vector`, `Vector(3)` round-trips, cosine-distance filter and order work); schema **no** — `dbUpdate` refuses a pack-declaring contract without the extension's on-disk migration package |
| A duck-typed fake `pg` client                                                    | **Works end to end** — six methods, canned `{ rows, rowCount }`, rows pre-decoded to JS values                                                                                                                              |
| A recording `beforeCompile`                                                      | Sees a plain-data AST with `kind` discriminators, byte-identical across runs, and the stamp as a plain object on `draft.meta.annotations`                                                                                   |
| `CollectionState` without executing                                              | Reachable on the collection's `state` field, marked `@internal`; no public accessor                                                                                                                                         |
| Contention                                                                       | **Not observable** — PGlite serialises every transaction                                                                                                                                                                    |

Two traps the harness must encode: the socket server defaults to one connection and the ORM's pool wants more (`maxConnections` at or above the pool size, or the driver dies with `EPIPE`), and the first-use contract-marker read opens a second connection inside a transaction and deadlocks on PGlite (`verifyMarker: false`).

## Decisions

- **An engine test asserts on behaviour through the secured surface against a real Postgres.** Rows in, rows out, `[]`/`null`/`0` on denial, hook spies for ordering. A **recording middleware** — a `beforeCompile` registered beside the engine's own — asserts structurally on `draft.ast` and `draft.meta.annotations` only where the built query is itself the subject: Access Filter merge, widen-and-strip, the Engine stamp's presence. SQL text is never asserted. Today's ~250 call-argument assertions are plan-shaped questions asked at the wrong layer; they become plan assertions or disappear.

- **Core adds no test-only seam to the wrapper.** No composed-Collection accessor, no state getter, no tripwire-skip flag. Every observation goes through Prisma's construction options handed to `getContext`, so the wrapper is opaque to tests exactly as to callers and the tripwire is taught nothing — a recording middleware is one more entry in the array and asserts the stamp rather than bypassing it. Same reasoning [#1043](https://github.com/OpenSaasAU/stack/issues/1043) used to refuse a plugin terminal seat: a second way in is a hole whether or not it is labelled test-only.

- **The database is an in-process PGlite per Vitest worker, honouring the `DATABASE_URL` escape.** No daemon, no Docker, no `prisma dev` for `pnpm test`. When `DATABASE_URL` is set the identical suite runs against that Postgres — CI's service container from [ADR-0003](0003-deployment-uses-postgres-and-prisma-migrate.md)'s amendment, or a developer's own. An **escape-only test** — one whose guarantee PGlite cannot exercise — skips visibly when the escape is unset, and CI always sets it, so the PR gate covers them. Today that set is ADR-0047's row-lock gate (PGlite cannot produce contention), ADR-0045's vector search (the schema blocker above), and anything needing real pool concurrency.

- **The harness always installs the tripwire, from the same core module the generator emits.** The engine suite runs under it, so a stamp regression fails a test rather than a login in production, and whatever [#1076](https://github.com/OpenSaasAU/stack/issues/1076) decides the tripwire becomes, the harness inherits without a decision here.

- **Core derives the contract; the CLI renders it.** A real-database engine test must build a runtime from a config object in-process, which needs `defineContract` input derived from the config. [ADR-0040](0040-the-generator-emits-a-typescript-contract-module-not-psl.md) placed emission in the CLI and was silent on derivation; the CLI depends on core, so derivation in the CLI would make core untestable without it. Core owns `deriveContract(config)` producing contract data from the field builders' structured type descriptors ([ADR-0049](0049-extension-packs-are-declared-the-tripwire-is-stack-owned.md)); the CLI renders that data to the literal Contract module. The generator's snapshot test becomes an equivalence: the rendered module and the programmatic derivation must produce identical contract JSON.

- **Consumers get a real context, not a fake of the surface.** `@opensaas/stack-core/testing` exports `createTestContext(config, session)` standing up a PGlite-backed context; UI, MCP, RAG and auth tests stop hand-faking `context.db.<list>.findMany`. PGlite and its socket and pgvector packages are **optional peer dependencies** of core, imported lazily by the testing subpath with a clear error if absent, so a production install carries no WASM Postgres. Pure-render UI tests that never touch data keep faking at the component-prop level, never the surface.

- **Isolation is an instance per test file and a truncate per test.** Each file gets its own PGlite with the schema applied once through the control client; tables are truncated between tests. Roughly half a second per file, and tests within a file share nothing.

- **The fake driver is not admitted.** It works, at Prisma's seam rather than ours, and a row-free hook-ordering test would run on it. Rejected anyway: one harness. PGlite is cheap enough that a second harness buys only drift between two ways of running the engine, plus hand-decoded canned rows per codec.

- **The corpus is rewritten by guarantee, not ported by file.** `packages/core/tests/` is ~21K lines built around delegate shapes and Prisma 7 semantics other records have already deleted — nested writes, `createMany`, fragments, `findUnique`. The new suite is organised by `CONTEXT.md` term: Silent failure, Access Filter, Field Visibility, Write Pipeline order, the two-phase read. ADR-0002's coverage ratchet stays and is re-baselined once.

## Considered options

- **A read-only `CollectionState` accessor on the wrapper.** Cheaper assertions than a middleware, and the state is there at runtime. Rejected: it is `@internal` in Prisma's types, and it is exactly the second way in the seam decision refuses — a test that reads composed filters is one cast away from a caller that does.
- **`startPrismaDevServer()` from `@prisma/dev`.** Prisma's own PGlite daemon, documented as unstable, one connection at a time, ports varied per suite, and it cannot install pgvector. Rejected: the in-process instance has none of those limits and no daemon.
- **CI's Postgres container only.** Rejected: it kills the zero-setup local loop for `pnpm test`, the one thing the PGlite choice buys.
- **An in-memory fake of the secured surface, shipped by core for consumers.** Rejected: a second implementation of every guarantee that drifts from the real one — the `packages/rag/src/storage/access-filter.ts` lesson [ADR-0038](0038-access-enforcement-stays-in-terminal-operations-with-the-spi-as-a-tripwire.md) already paid for.
- **Transaction-rollback isolation.** Fastest, but the engine's own transactions nest inside it and PGlite serialises, so anything concurrency-shaped becomes untestable even under the escape.
- **Per-worker instance shared across files.** Cheaper startup, but every file would declare the same contract or re-apply schema, and cross-file leakage is possible.
- **Harness-side raw DDL for extension columns**, so vector tests run on PGlite. Rejected for now as a second schema path in test code; if Prisma's layout check learns to take a pack's shipped migration, vector tests move onto PGlite with no decision here changing.

## Consequences

- **`write-pipeline.ts`'s `$transaction`-absence heuristic is deleted, not replaced.** [#1036](https://github.com/OpenSaasAU/stack/issues/1036) found `ctx.scope` retires it; this record removes its other reason for existing — no client lacking `transaction` can be constructed, so there is no "test mock" branch. The Unowned join term keeps its application-managed-transaction case and loses its test-double case.
- **ADR-0002 is amended in place.** The PR gate now runs real-database tests; the cold-clone nightly from #1040 is unchanged. ADR-0041 gains a note that opacity extends to tests. ADR-0040 gains the derivation seat. ADR-0049 gains the harness as a second, identical registration of the tripwire.
- **Three items join the CLI re-verification gate**, all `8.0.0-rc.8` findings the harness encodes as workarounds: the socket server's `maxConnections` requirement, the `verifyMarker` deadlock on a single-connection database, and whether `dbUpdate`'s layout check still refuses a pack-declaring contract.
- **The consumer sweep widens a tenth time.** The core `tests/` rewrite; UI, MCP, RAG and auth test doubles replaced by `createTestContext`; per-package Vitest configs; CI workflows setting `DATABASE_URL` on every job; PGlite packages as optional peers of core and dev dependencies of every package with a suite.
- **Numbered 0057.** 0056 was taken on `main` by the Unsafe-surface record when this was written.
