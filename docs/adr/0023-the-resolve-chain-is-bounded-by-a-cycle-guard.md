# The resolve chain is bounded by a cycle guard, not a depth cap

A `resolveOutput` hook may issue its own read, whose rows run their own `resolveOutput` hooks, which may read again — a cycle the engine had no bound on at all, so an ordinary cyclic schema drove the server to the V8 heap limit (#844). We decided the bound belongs on **hook execution** rather than on include expansion, and that it is a **cycle guard over (list, field) pairs** — a hook already on the current resolve chain is refused — with a named depth cap kept alongside purely as a cost limit. Chain state is carried per hook invocation on a derived context, not accumulated on one mutable counter shared by the whole request.

The bound had to go on hook execution because that is where the cycle actually lives: two lists with **no relationship fields whatsoever**, whose virtual hooks read each other, recurse forever. The auto-include only feeds the cycle extra rows to walk, so every include-side bound (a depth cap on the auto-include, or extending the Access Filter's `visitedLists` guard across the hook boundary) fixes the reported reproduction while leaving the general loop intact. This also means the runaway is not a 0.33.0 regression: the unbounded chain predates it, and what changed was only how easily an ordinary schema reaches it.

## Considered Options

- **A pure depth cap on the chain** (refuse to run hooks past depth N; N=1 being "hook-issued reads compute no virtuals"): rejected because it draws the line in the wrong place. A virtual `Order.total` that reads line items whose own `LineItem.subtotal` is virtual is acyclic and terminates; a depth cap breaks it at an arbitrary number and does so by omitting the field, so the caller sees `undefined` where the generated type promises a value. The cycle guard refuses only what genuinely cannot terminate.
- **Reverting to the pre-0.33 "compute no include inside a hook" behaviour**: this is the reporter's own isolation patch and it does stop the runaway, but it is a straight revert of ADR-0022's first-hop fix — it fails that change's regression coverage and reinstates the fail-open where a hook-issued read returns unscoped relation rows. A hang is not worth trading for a silent leak.
- **Dropping the cost cap and keeping only the cycle guard**: rejected. Chains are finite once no pair repeats, but fan-out is multiplicative — each generation fetches rows × rows — so an acyclic chain can be ruinously expensive while being perfectly terminating. Same division of labour as the Access Filter, where the cycle guard is what prevents infinite recursion and the depth cap is an honest cost limit.
- **Carrying the chain in `AsyncLocalStorage`** rather than on the context: rejected. It would be the first implicit control-flow mechanism in the codebase; this subsystem threads `depth` and `visitedLists` explicitly everywhere else, and explicit threading solves the problem without a runtime-dependent mechanism.
- **Keeping the old shared counter alongside the new chain**, deprecated: rejected. The two are not the same quantity — the chain is per hook invocation, the counter was per request-in-flight — so any bridge value would be a lie for some caller. Two signals for one fact, kept in sync by hand, is the failure mode ADR-0022 was written about.

## Consequences

- **A self-referential hook now throws where it used to hang.** This cannot break a working application: a repeated (list, field) pair never terminated, so no shipped app depends on it. The error names the chain, which is the whole point — silence here would render `undefined` into a UI with nothing to grep for. The cost cap, by contrast, **can** be reached by an acyclic chain that works today, so exceeding it omits the field and warns rather than throwing.
- **The `resolveOutput` guard on the read path becomes accurate**, which fixes a second, independent defect present in both 0.32 and 0.33: because the old counter was shared and mutable, a plain top-level read that merely ran concurrently with an unrelated hook observed "I am inside a hook" and silently collapsed its nested auto-include. Sibling hooks on one read were counted as depth 3, 2, 1 rather than 1, 1, 1. Concurrent reads stop losing nested relations.
- The context field carrying this state changes shape. It is underscore-prefixed internal plumbing, but it sits on a publicly exported type, so hand-built context mocks must be updated — a compile error, not a silent break.
- ADR-0022's read-path decisions stand; only its claim that loop prevention was unaffected by the first-hop change is corrected there. Nothing in this record reopens what a caller-supplied include may return.
