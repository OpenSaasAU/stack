# Extension packs are declared in the config; the tripwire is stack-owned

[#1040](https://github.com/OpenSaasAU/stack/issues/1040) deleted `prismaClientConstructor` — Prisma 8 hands the app no client class to wrap — and with it the db config's only extension point, deliberately leaving the hole unfilled. Two things then needed a seat and neither had one: [ADR-0038](0038-access-enforcement-stays-in-terminal-operations-with-the-spi-as-a-tripwire.md)'s `beforeCompile` tripwire, and the Prisma 8 extension packs [ADR-0045](0045-vector-search-is-an-engine-owned-terminal-over-a-native-vector-column.md) made blocking by adopting `@prisma/orm-extension-pgvector` for the native `Vector(n)` column.

They do not share a seat, because they are not the same kind of thing, and Prisma's own runtime says so first — `PostgresOptionsBase` carries `extensions` and `middleware` as two separate arrays. An **extension pack** is app- or plugin-declared capability that is visible in the contract; the tripwire is stack-owned middleware that is invisible to it.

## Decisions

- **`db.extensions` holds import descriptors, not pack values.** `[{ name: 'pgvector', from: '@prisma/orm-extension-pgvector/pack' }]`. ADR-0040's contract module is standalone and fully literal, so the generator cannot serialize a live object out of `opensaas.config.ts` into it — it can only re-emit an import. `name` is load-bearing twice: it is the binding the generator emits, and the key in `extensionPacks` that spells `type.pgvector.Vector(n)`. This is the shape `virtual({ type: { value, from, name } })` already uses for the same reason.

- **One declaration, three emissions.** `db.extensions` lands in the contract module (`defineContract({ extensionPacks }, …)`), in `prisma.config.ts` (`ormConfig({ contract, extensions })`), and in the generated runtime client. Prisma's `db verify` reports _"Extension mismatch — the contract requires an extension that is not wired in the config"_; for a generated project that state is unreachable, because the three sides are one source. `db verify` stays a backstop against hand-edited artifacts, not our error channel.

- **The mismatch that survives is a field, and it is a generate-time error.** A field whose type needs a pack the config does not declare fails `pnpm generate`, naming the list, the field and the missing pack — the shape `db.indexes`' validation errors already use. So the field-builder contract replacing `getPrismaType()` carries a **structured type descriptor** — `{ pack: 'pgvector', type: 'Vector', args: [1536] }` — from which the generator both resolves the requirement and emits the expression. Not an expression string with a `requires` list: that is the regex-shaped seam ADR-0040 deleted `extendPrismaSchema` to be rid of.

- **A plugin may contribute a pack**, through `PluginContext.addExtension({ name, from })` — a fifth verb beside `addList`, `extendList`, `registerFieldType` and `registerMcpTool`. `ragPlugin` knows it needs pgvector; the app author configuring it has never seen that pack's name, and without this every RAG project meets the error above on its first generate. ADR-0040's purity is untouched: the declaration is strings, resolved during config evaluation and emitted as an import, exactly as plugin-contributed lists already reach the generator. A duplicate `name` is idempotent when `from` agrees and a generation error when it does not — two packs claiming `type.pgvector` is not something to merge.

- **The tripwire is not in the config at all.** The generator emits it unconditionally into the runtime client's `middleware` array. This is what keeps ADR-0038's promise literally true: if the SPI churns at GA, deleting the tripwire is deleting one generator line, not a breaking config change in every app that named it. It also means an app cannot omit it, so a security backstop never becomes opt-in.

- **The stamp is a Prisma annotation, and the fail-open objection inverts.** [#1033](https://github.com/OpenSaasAU/stack/issues/1033) found `defineAnnotation()({ namespace, applicableTo })` writing to `plan.meta.annotations[ns]`, read in middleware via `handle.read(plan)`, and warned that annotations are fail-**open** for access control because they are per-call-site. That warning is about carrying a _session_: a forgotten `.annotate()` there lets an unscoped query run. Here the annotation carries only "this came from a declared surface", and its **absence is what throws** — per-call-site is exactly right when the default is refusal. Both stamps live in one namespace; the engine applies its own inside the terminal, so no application call site ever writes one.

- **The Unsafe surface stamps every query it builds.** One place applies the intentionally-unscoped stamp: the renamed `context.prisma`, whose name already states the bypass. Better-auth's adapter gets it by construction, being handed that surface through `rawOpensaasContext` ([ADR-0060](0060-better-auth-is-driven-by-a-stack-authored-auth-adapter-over-the-unsafe-surface.md) names the construction — a stack-authored Auth adapter over this surface's ORM lane, with two operations on its typed SQL lane — since better-auth has no adapter for a Prisma 8 client); core's own internals get it the same way. "Who may stamp" is therefore answered by "who may reach that surface" — already an audited, named act — rather than by ceremony at each call site, where a forgotten stamp would be a throw in production login. Exempting auth by a separate client instance stays rejected for ADR-0038's original reason: the exemption would attach to a client, so anything sharing it inherits it.

- **Middleware, annotation and terminal write are one deletable component.** Core exports them together and the generator wires them in one line. Deleting the tripwire removes the generator line and the core module, and the terminals lose an `annotate()` call — nothing is left writing to a namespace nothing reads.

- **`db.client` is a second and deliberately different seat.** `{ poolOptions?, pg?: () => Pool }`. `prismaClientConstructor` served two jobs and #1040 retired only one: adapter selection is genuinely gone, but binding a specific pool is not, and Prisma 8 keeps it reachable via `postgres({ contractJson, pg })`. Without this seat the generated context is unconditionally `postgres({ contractJson })` and serverless Postgres — the documented `PrismaNeon` + `neonConfig.webSocketConstructor` recipe — has nowhere to configure itself. A **lazy factory**, not an instance: config is loaded by the CLI and by tooling that never issues a query, and none of it should open a connection.

- **The two seats have opposite shapes, deliberately.** `db.extensions` is declarative strings because it reaches the pure contract module; `db.client` is a live callback because it reaches only `.opensaas/context.ts`, which carries no purity constraint. Folding them together would conflate a contract-visible capability declaration with per-deployment runtime wiring — different lifetimes, different purity rules.

## Considered options

- **One shared seat for packs and the tripwire.** Rejected: it makes deleting the tripwire a breaking config change everywhere it is named, and lets an app omit it.
- **`db.extensions: [pgvector]`, the pack value itself.** Reads better, but the generator would have to reverse-engineer an import specifier from a runtime value it cannot introspect.
- **Inferring the pack set from the fields actually used.** No error is possible, but the config stops stating its own dependencies and an app can silently acquire a Postgres extension requirement.
- **A full client callback, `client: (postgres) => Client`.** Closest to the deleted constructor, and rejected for the same reason it was deleted: it reaches past pool binding into contract wiring the generator owns.
- **Reserving `options` on the descriptor now.** No known pack takes options; adding the key later costs nothing under this map's standing "breaking changes are fine" preference, and emitting an argument nothing consumes is speculative generality on a surface ADR-0040 spent a record simplifying.

## Consequences

- **`CREATE EXTENSION vector` is the deployment's job, and is documented.** Declaring a pack is a contract-level act; the Postgres extension still has to exist. That belongs to whoever provisions the database, documented beside the `DATABASE_URL` escape ADR-0003 already defines for exactly this set of cases (pgvector, e2e concurrency, CI, Windows). `examples/rag-openai-chatbot/scripts/install-pgvector.ts` — named in ADR-0038 as the one consumer the `context.prisma` rename breaks — is ported rather than deleted. Running the DDL from `db:update` was rejected: it needs privileges the stack should not assume, and cannot work on `prisma dev` at all, so the convenience would be absent in precisely the default dev loop.
- **`.opensaas/types.ts` and `prisma.config.ts` both gain generator inputs**, which narrows two of the map's open fog patches rather than settling them.
- **ADR-0038, ADR-0040, ADR-0045 and ADR-0003 are amended in place**; none is superseded. 0038 gains a registration and a stamp mechanism, 0040's "preview features are extension packs" gains the option that declares them, 0045's named hole is closed, and 0003's deleted constructor has the pool-binding half of its job re-owned.
- **Two items join the CLI re-verification gate**, both structural-but-unproven at `8.0.0-rc.8`: whether `handle.read(plan)` can actually read an annotation inside `beforeCompile` (no shipped middleware or test does it — the map already carries this one, and this decision now rests on it), and whether `ormConfig` genuinely needs `extensions` when the contract already names them. If the second turns out to be redundant, the emission map shrinks from three files to two and no decision here changes.
- **Numbered 0049 after a fourth collision.** 0048 was free on every pushed branch when this was written and was claimed by [#1047](https://github.com/OpenSaasAU/stack/issues/1047)'s renumber minutes later. Per the map's own rule, the later commit moves.

## Amendment — the test harness is a second, identical registration (ADR-0057)

The generator is not the only thing that constructs a runtime client: [ADR-0057](0057-engine-tests-run-against-an-in-process-postgres-through-the-clients-construction-options.md)'s `createTestContext` builds one without the generator, and it installs the tripwire unconditionally from the same core module the generator emits. The engine suite therefore runs under the tripwire, and whatever [#1076](https://github.com/OpenSaasAU/stack/issues/1076) decides the tripwire becomes reaches the harness through that one module with no test-side change.

## Amendment — the stamp is an ambient origin, not an annotation (ADR-0059)

[#1073](https://github.com/OpenSaasAU/stack/issues/1073) measured that a Prisma annotation attaches to **one compiled plan per terminal**: the identity `SELECT` before `update()`/`delete()` and every statement of a nested write are built from `emptyState()` and cannot carry it, so the tripwire above, as specified, would have refused the secured surface's own `update()`. [ADR-0059](0059-the-engine-stamp-is-an-ambient-origin-the-executing-surface-enters.md) keeps this record's decisions and changes the stamp's mechanism: the Engine stamp is an **ambient origin** — an `AsyncLocalStorage` store the executing surface enters around exactly the execution it performs, holding `'engine' | 'unsafe'` and nothing else — which every statement of a logical call shares. The "fail-open objection inverts" bullet holds with its object changed: per-scope is exactly right when absence is refusal. The "one deletable component" bullet holds: store, tripwire and error are one exported module, and a terminal loses a scope entry instead of an `annotate()` call. The Unsafe surface's bullet holds in substance — its executors and its ORM-lane proxy enter the unsafe origin — and "no application call site ever writes one" is now true of a scope rather than an annotation. The `handle.read(plan)` re-verification item above is moot rather than answered.
